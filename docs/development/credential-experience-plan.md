# 凭据体验实施计划

状态：主体实现与审查修复已完成；最终验收须核对候选提交对应的原生运行证据。设计依据为[已确认的体验决策](./credential-experience-design)。

## 阶段 1：核对入口和配置契约

- 梳理所有配置加载、凭据读取、认证、成功回调和保存入口，标出只读路径与交互能力。
- 明确默认库 ID、目录及 key-file 路径，复用跨平台路径规则，避免写入二进制所在目录。
- 明确显式 none 与未选择后端的识别方式；确定单次不保存、全局关闭保存的参数、优先级和对自动迁移的影响。
- 确定密码拒绝与其他认证失败的分类、重试上限、共享私钥口令归属及成功验证信号。
- 审查 v1 升级与 v2 后端迁移能复用的事务组件，明确命令、恢复、源数据清理语义。

交付：入口矩阵、配置/命令契约及边界测试清单。涉及未确认的用户可见取舍时先讨论，不自行改写已确认决策。

## 阶段 2：默认离线库与自动保存

实现惰性初始化、跨进程并发初始化、key-file 生成/复用，以及三类可保存秘密的验证成功回调。保持配置引用与秘密分离。加入保存失败继续连接和读取失败交互重输；无人值守明确失败。

## 阶段 3：认证失效与更新

实现有限且可取消的认证重试，严格按验证结果更新。覆盖 sudo 和仅允许普通用户登录后 su 的服务器；私钥解锁验证独立于 SSH 最终结果。一次性输入不持久化。

## 阶段 4：自动升级与高级迁移

实现正常使用入口的自动升级，沿用备份、写入、读回、CAS 和持久化确认顺序。覆盖中断恢复与旧配置继续使用。实现从已迁移 v2 离线库到其他后端及返回的显式迁移，区分默认后端变更与已有引用迁移，禁止自动删除源凭据和恢复材料。

## 阶段 5：双语文档与发布门禁

同步中英文快速开始、凭据指南、迁移指南、故障排查、CLI 帮助及更新说明。把[发布草案](./credential-experience-release)转换成与已验证实现一致的用户说明，补上真实路径、配置项、完整迁移命令和恢复步骤。未完成实现不得移除“待实现”标记。

## 实施进度（未发布）

已实现新安装默认离线库 + key-file、写入时初始化、旧配置自动迁移和 never 退出规则；显式后端选择与恢复材料保留。默认库位于配置文件旁的 `credentials/`，密钥为 `credentials.key`。读取与 dry-run 不初始化库；中断的初始化事务仍需显式恢复。

SSH 登录密码和私钥口令支持有界重输；交互读取失败可以临时输入，保存失败保留连接并禁用不确定版本的后续写回。快照冲突、取消和无人值守路径保留错误行为。

### 普通命令、脚本与流式提权

`RunWithSudo`、`RunScriptWithSudo` 和 `RunCommandWithIO` 已使用独立的提权握手：远端在用户命令之前发出随机就绪信号，收到客户端确认后才执行命令。就绪信号不作为完整字面量出现在远端命令中，避免命令回显误触发。双方确认前不转发脚本或用户输入；密码只在收到认证提示时发送。

sudo 在同一进程内最多尝试三次密码；su 仅在明确拒绝认证、且尚未收到就绪信号时重建认证会话，最多三次。用户命令一旦可能开始就不自动重跑。未知错误、输出故障、取消和超时不触发此重试。无人值守调用仍提前检查凭据并报错。

收到就绪信号并完成密码交换即可确认密码，用户命令非零退出不再阻止保存，也不被当成密码错误。退出码继续返回调用者。交互调用保存失败保留连接并禁用后续写回；免密/缓存命中的交互调用不读取、发送或保存密码。

sudo 使用独立提权引用，缺失时以带版本校验的登录密码作为候选。旧 SuPwd 不作为 sudo 密码；已有 su 引用不会被自动改作 sudo 引用。自动转向 su 不预先索要并丢弃 root 密码，不增加额外 su 预检。

验收覆盖：重输后命令只执行一次、非零命令退出仍保存有效密码、三次失败不消耗命令输入、不保存错误密码、免密输入无凭据混入、分片信号和命令输出透明性、取消时协程退出。实际 Bash 测试验证确认值错误或缺失时命令不执行，并验证确认行不会混入 stdin。

### 独立交互式 PTY

`ShellWithSudo` 和 `RunInteractiveWithSudo` 已接入同一认证握手，并提供借用调用方输入输出的 `ShellWithSudoIO` / `RunInteractiveWithSudoIO`。认证提示期间本地终端保持正常模式；认证成功后才切换 raw。远端 PTY 的密码和确认阶段关闭回显，收到确认后使用 `stty echo` 恢复回显并发出终端交接信号，客户端随后才转发键盘输入。远端使用 Bash 和标准终端工具完成交接。

重输不会重复执行已可能开始的命令。交互 shell/exec 保留原有的普通进程退出码处理；认证失败、取消、输入输出错误、恢复错误不会被普通退出码掩盖。密码验证成功后，即使交互命令非零退出仍可保存。

窗口尺寸监听可取消并等待退出。stdin 读取器停止、尺寸监听退出后恢复原有终端模式，再返回调用者。Linux 实际 PTY 测试覆盖密码输入时的 canonical 模式、首字符传递和模式恢复；实际 Bash/PTY 测试验证确认行不回显、交接后恢复回显。取消、交接超时及恢复失败另有确定性测试。Windows/macOS 的最终原生运行门禁仍待执行。

### TUI 接入

Enter、监控和日志连接使用 `tea.Exec` 先释放终端，再认证。每次操作拥有连接器，取消时在界面恢复前等待共享 SSH 握手退出。带作用域的接口禁止后台提示和自动写回，并将后台凭据读取标记为非交互。SSH 使用当前仓库而非另起 CLI 子进程；返回时刷新引用、筛选、当前节点和勾选状态，认证保存后又发生错误的路径也会刷新。

TUI 继承保存策略并支持 `--remember` 覆盖。`never` 禁止自动迁移和自动保存，显式管理操作仍可用。自动保存初始化失败允许仅会话连接并显示状态；写回失败保留已认证连接，恢复界面后继续显示未确认保存的提示。解锁使用释放终端后的可取消上下文。

测试覆盖实际 SSH 认证、Linux PTY Enter 会话、同仓库保存、always/ask/never、目标变更后的新连接、后台不提示/不写回、终端释放失败、取消、保存失败及筛选保留。共享 SSH 输出按写入片段串行化，避免同一目标缓冲区通过 `io.ReaderFrom` 优化发生竞争。

### v2 后端迁移

`credential migrate --to <store>` 现支持 v1 升级和 v2 后端迁移。v2 对当前引用去重、复制到新引用、读回比较内容与到期时间、CAS 切换全部引用和默认库；never 不阻止显式迁移。源凭据保留，旧 v1 材料和 v2 迁移记录独立。普通中断重跑原命令；并发配置修改可显式 `--restart` 归档旧计划后重新规划，不回滚、不删凭据。

测试覆盖共享引用、三种凭据、离线库往返与 key-file 复用、dry-run 无写入、中断恢复、配置冲突与重新规划、目标损坏、不确定写入及 v1 备份保留。此处的离线往返证据来自本地 Linux；六平台最终原生验收仍独立进行。操作示例见[迁移指南](../guide/migration)。


### 审查修复与原生验证门禁

离线库损坏错误通过凭据服务的不可用错误分类传递，保留原始原因；交互可临时输入，非交互与取消仍失败关闭。真实损坏库测试覆盖认证成功、失败写回后保留连接、原密钥和损坏 CURRENT 不变。

CLI 自动保存服务初始化失败时，SSH、交互 exec、单目标 SCP 与 TUI 一样允许仅会话使用；显式禁用所有自动写回，避免回落到旧配置保存。回归覆盖 always/ask/never、非交互边界、提示输出失败及配置保持不变。

六平台工作流增加配置层初始化/迁移、真实损坏库恢复和 Windows ConPTY 检查。新增原生系统后端往返测试需显式设置 XOPS_TEST_NATIVE_MIGRATION=1：CI 为 Linux 启动隔离 Secret Service，为 macOS 创建临时 Keychain，Windows 使用 Credential Manager。测试使用随机测试引用，读回三类凭据、保留源引用并验证 key-file 复用，结束后清理测试系统凭据。未配置服务时的 skip 不算原生验收通过。

这些门禁不替代完整的 Windows/macOS TUI 与提权终端体验验收，也不证明物理断电恢复。发布前仍须核对最终提交的运行结果。

原生凭据测试使用临时目录的真实路径，避免 macOS 的 /var 符号链接误触发路径拒绝；生产环境仍严格拒绝符号链接目录。Keychain 清理仅在测试钥匙串创建成功后执行。
