# MCP Streamable HTTP 与文件流转发设计

状态：HTTP 入口、实例化 Runtime、任务日志、SFTP 流转发和离线恢复已实现。协议与客户端验证记录见第 2 节；部署与操作步骤见[使用指南](../guide/mcp-http)。

## 1. 范围与目标

| 项目 | 设计约束 |
| --- | --- |
| 客户端 | Codex、Antigravity CLI，通过远程 Streamable HTTP 连接 |
| 部署 | 单进程、局域网、同一套节点与凭据、共享 Bearer Token |
| 传输 | 保留 stdio；新增 `/mcp`；不实现旧版 HTTP+SSE `/sse` |
| 文件数据 | 客户端本地命令与 HTTP 接口收发二进制，服务端通过 SFTP 转发 |
| 文件范围 | HTTP 首期仅普通单文件；目录由客户端打包；服务端不解包 |
| 排除项 | OAuth、多用户权限隔离、本地 MCP 桥接、断点续传、自动重试文件写入、多实例调度 |
| 兼容性 | stdio 工具名称、参数、同步完成语义及既有目录传输行为保持不变 |

服务端不保存完整文件内容，不通过 JSON/Base64 或模型上下文传递二进制。目标服务器上的上传临时文件、客户端上的下载临时文件，以及服务端少量任务元数据不属于中转文件缓存。

## 2. 协议与客户端验证门槛

Streamable HTTP 是传输方式，协议修订日期是另一项兼容性。支持 HTTP 或展示工具列表不代表支持最新请求生命周期及审批机制。

当前采用 SDK 提供的有状态 `2025-11-25` Streamable HTTP，以目标客户端可用修订为基线。Codex 0.156.1 实测不能连接仅支持 `2026-07-28` 的服务；新版 SDK 的可用修订并不等于客户端已经支持。服务显式限制协议基线，不增加旧版 HTTP+SSE 端点。

客户端验证记录（2026-09-26）：使用回环 HTTP 与内存 SSH/SFTP 目标，未对生产服务器写入。

| 客户端 | 已覆盖 | 限制 |
| --- | --- | --- |
| Codex 0.157.0 app-server | 发现、工具调用、审批同意/拒绝/取消、上传及下载保存闭环 | 审批结果由测试控制器提供，不代表手动 UI 操作验收 |
| Antigravity CLI 1.2.11 | 发现、上传/下载任务创建、本地控制器执行辅助程序后的文件闭环 | 审批表单自动取消；CLI 自身的终端命令权限流程未纳入测试 |

Antigravity 的审批同意路径不能标记通过，所需审批的操作保持拒绝。桌面/IDE 不在验收范围，客户端自身的工具确认不等价于 XOps 审批。

HTTP 基线使用 elicitation；其他协议修订的 InputRequests 不混用于该连接。协议变更须重新运行客户端矩阵。新 HTTP 配置默认对不支持审批的调用拒绝执行，现有 stdio 的显式 fallback 保留；拒绝、取消、错误和超时均不放行。

Agent 实际命令执行环境还须具备局域网可达性、本地文件权限和认证材料。MCP 宿主可达不代表远程沙箱可达。版本探测不启动桌面应用或触发升级。

参考：[Codex MCP](https://developers.openai.com/codex/mcp/)、[Antigravity MCP](https://antigravity.google/docs/mcp/)。这些文档说明 HTTP 和 Header 配置，不足以证明具体协议修订的端到端兼容性。

## 3. 运行结构与配置

`cmd/mcp.go` 作为组合入口加载配置和凭据；`Runtime` 实例持有 SDK Server、SSH 连接器、护栏、传输管理器和审计器，消除 MCP 包级连接器和配置变量。工具通过显式依赖注册，不从全局变量读取运行资源。

HTTP 管线分为认证及 Host/Origin 校验、MCP Handler、传输 HTTP Handler。MCP 协议交给 SDK；传输管理器不依赖 SDK 的临时 `ServerSession` 对象。

配置优先级为显式 CLI 参数、YAML、默认值。公共选项为 `--transport stdio|http`、`--listen`、`--public-url`、`--token-file`、`--token-env`、`--state-dir`、`--allowed-hosts` 和 `--allowed-origins`；秘密也可通过指定环境变量读取，不提供明文 Token 参数。默认仍为 stdio；HTTP 默认监听 `127.0.0.1:8080`，局域网地址需显式配置。启动前校验冲突、地址、配置和凭据可用性。

HTTP 服务配置在运行期间使用固定快照，不做热重载；重启使旧的未执行授权失效。已有凭据非交互边界、主机密钥验证及 ProxyJump 行为保留，不通过 HTTP 提供凭据解锁或录入窗口。

Runtime 根上下文管理连接保活、任务和清理器。创建任务的 MCP 请求结束不取消已创建任务；流传输请求的上下文只控制相应传输。不得在持有全局锁时等待网络 I/O 或资源关闭。

`xops mcp` 和 `xops mcp serve` 共用参数校验及启动逻辑。stdio 的 stdout 仅输出协议数据；HTTP 启动信息和诊断使用 stderr，并对认证 Header 脱敏。

## 4. MCP 与 HTTP 接口契约

HTTP 工具集复用现有节点、命令和远程文件操作，替换两个依赖服务端本地路径的文件传输工具：

| 工具 | 输入与结果 |
| --- | --- |
| `xops_prepare_upload` | `requestID`、`nodeID`、`remotePath`、`size`、`sha256`、`overwrite=false`；返回已准备任务 |
| `xops_prepare_download` | `requestID`、`nodeID`、`remotePath`；返回源文件信息及已准备任务 |
| `xops_transfer_status` | `transferID`；返回状态、阶段、字节数、摘要、时间、错误及清理情况 |
| `xops_transfer_cancel` | `transferID`；幂等取消，提交阶段返回当前状态而非伪造取消成功 |

HTTP 不暴露原有 `xops_upload`、`xops_download` 的服务端 `localPath` 参数；stdio 继续注册原工具。新增名称同步加入风险分类、参数 Schema 和文档，不能依赖未知工具的默认风险级别。

准备结果包含 `transferID`、`operationID`、`state=ready`、固定来源的传输 URL、方法、所需 Header、大小/摘要信息、`startBefore` 和 `statusExpiresAt`。不得返回长期共享 Token。客户端本地路径仅由本地命令读取，不作为服务端文件系统路径处理。

| HTTP 接口 | 行为 |
| --- | --- |
| `POST /mcp` | SDK 管理的新协议请求及流式响应，使用服务认证 |
| `PUT /v1/transfers/{id}/content` | 上传请求体，`application/octet-stream`，任务认证 |
| `GET /v1/transfers/{id}/content` | 下载响应体，任务认证 |
| `GET /v1/transfers/{id}` | 可重复查询该任务状态，任务认证 |
| `DELETE /v1/transfers/{id}` | 幂等取消该任务，任务认证 |

数据接口只接受已批准任务记录中的操作，不接受新的节点、远程路径、覆盖策略或来源 URL。未准备或未授权的请求不得拨号、打开文件或写入目标。HTTP 错误返回稳定错误码和操作 ID；流响应已开始后的错误必须记录到任务状态，不能仅依赖 HTTP 状态码。

MCP 返回结构化任务，不返回需要直接执行的服务端脚本。提供 POSIX shell 与 PowerShell 的固定客户端流程；`curl` 可作为基础数据传输工具。可选辅助程序 `scripts/mcp/transfer.py` 实现来源验证、流转发和本地校验提交，不作为必需安装项，不运行本地 MCP 桥接。

## 5. 认证与审批边界

共享 Bearer Token 仅用于 MCP 及其管理工具。每个任务生成独立、高熵的短期 Bearer 凭证，仅授权该任务的规定方向、状态查询和取消；任务 ID 本身不构成授权。服务端只保存任务凭证的摘要，使用常量时间比较，不在日志、URL、错误或任务列表中回显凭证。

`startBefore` 限制启动传输，状态凭证期限独立；过了启动期限不能再开始数据流，但仍可查询终态。在期限内启动的大文件不因启动期限经过而被截断。数据流的重复启动通过原子状态转换拒绝；状态查询不会消耗启动机会。

审批绑定服务实例/认证域、操作类型、已解析目标、规范化路径、覆盖策略及完整参数摘要，任务凭证不依赖 MCP 会话继续存活。共享 Token 表示同一信任域，不声称能区分多个持有者或阻止同一主体主动转交凭证。审批挑战仍要求 `approved=true`、两分钟有效、单次消费；错误、拒绝、取消和过期不产生传输授权。

规范化和解析后的路径进入护栏检查，原始路径及真实路径均检查保护策略。授权和传输参数在任务生命周期内不可修改。HTTP 数据接口校验授权、有效期和状态，不再次绕过审批创建新任务。

记录 `authorized`、`ready`、`started`、`commit_started`、终态及清理事件，保持同一 `operationID`。需要先记录执行意图再产生远程副作用。任务创建不能沿用“handler 返回即 executed”的同步审计逻辑。提交成功后审计写入失败返回“已提交，审计异常”，不得引导重试。

局域网默认也需要 Token。HTTPS 优先由现有反向代理终止，不增加证书签发系统；显式使用 HTTP 时不声称凭证或内容已加密。原始请求 Host/Origin 按配置白名单校验；原生客户端无 Origin 可使用有效认证连接；不启用宽泛 CORS，不盲信转发 Header。公开 URL 来源于可信配置，客户端不得将凭证转发到不同来源的重定向目标。反向代理关闭流接口缓冲，并配置适合流传输的超时。

## 6. 单文件传输流程

### 上传

1. 客户端确认普通文件，计算大小及 SHA-256；提交准备任务。文件在计算后发生变化时，以最终摘要不匹配拒绝提交。
2. 服务端完成目标解析、护栏和审批，持久化不可变任务记录后返回 `ready`。准备任务不预先打开并长期持有远程文件。
3. 数据请求认证后，在一次原子调度操作中检查并取得并发额度、目标写入权及任务所有权，再建立专属 SFTP 子系统。额度不足或目标忙时返回繁忙，保留 `ready` 且不消耗启动机会；已经成功占用后失败的任务不允许重用数据入口。
4. 在目标文件同目录以随机任务名、独占创建及原子的 `0600` 权限建立临时普通文件，记录所有权和路径。不得复用其他任务或此前残留的临时文件。
5. 固定缓冲区转发并增量计算摘要；校验声明长度、实际长度及摘要。过短、过长、非普通文件、写入或关闭错误均不进入提交。
6. 复查目标路径和覆盖条件，先持久化 `committing`，再执行目标端提交。首次创建使用经验证不会替换既有目标的 rename 语义；显式覆盖要求原子替换能力，不使用备份加重命名降级。
7. 持久化终态并返回结果；清理错误单独记录。网络断开导致无法判定 rename 是否生效时进入 `unknown`，不得断言原文件未改变。

默认 `overwrite=false`。同一已解析 SSH 目标、账户和规范化目标路径的传输写入互斥；配置别名不能绕开同目标锁。锁只协调本服务的传输任务，不约束外部程序、任意 SSH 命令或其他客户端的写入。不以 `Stat` 后无条件替换实现“不覆盖”。

目标已有符号链接、目录或特殊文件时拒绝上传；父路径解析并执行保护路径检查。SFTP 无法通用地提供针对外部进程改写父目录的完整无竞态路径约束；目标目录须受可信账户控制，路径检查不宣称等价于操作系统沙箱。

上传默认创建权限为 `0600`，不支持所有权、ACL、扩展属性及原文件元数据完整保留；显式覆盖也采用该文件模式，在工具说明和审批信息中明确。需要保留权限的需求作为后续独立功能。

### 下载

1. 准备任务时读取普通文件元数据；开始传输时重新检查，并在同一打开句柄上读取。源文件是目录、符号链接或特殊文件则拒绝。
2. 服务端向 HTTP 响应流转发并计算 SHA-256。发送结束后保存字节数、摘要及 `streamed` 状态。错误必须在任务状态中保留，即使响应已返回 200。
3. 客户端在目标同目录独占创建临时文件，检查命令退出状态，再查询任务状态并核对本地大小和摘要。
4. 只有服务端为 `streamed` 且本地校验通过，客户端才提交本地文件并报告下载完成；默认拒绝覆盖本地已有文件。服务端不声称能够观察客户端磁盘提交。

客户端脚本对正常错误和中断清理自己创建的临时文件，保留原目标；客户端异常退出导致的残留由客户端识别处理，不纳入服务端文件清理。不得因服务器状态为 `streamed` 而忽略本地磁盘写入、关闭或改名错误。

摘要证明客户端收到的字节与服务端发送的字节一致，不证明源文件在并发写入期间具有快照一致性。明显的大小/元数据变化按失败处理；需要一致快照时，源文件应先由目标侧生成稳定副本。

首期不支持 Range、追加或续传。零字节文件仍走长度、摘要及提交检查。上传和下载的最终文件名均来自已批准参数或客户端明确路径，不由响应 Header 自动选择。

## 7. 状态、幂等和恢复

| 状态 | 定义及后续处理 |
| --- | --- |
| `ready` | 已授权、尚未启动，可以取消或过期 |
| `transferring` | 单个数据请求持有任务，不允许第二次启动 |
| `verifying` | 检查长度、摘要及上传关闭结果，尚未提交 |
| `committing` | 上传提交意图已持久化，正在执行远程 rename |
| `completed` | 上传提交已确认并记录；与客户端收到成功响应无关 |
| `streamed` | 下载字节发送和服务端摘要已完成；不是本地保存确认 |
| `failed` | 已知失败，包含阶段与是否需要清理，不等价于所有副作用均已撤销 |
| `cancelled` | 已确认在提交前停止，临时文件清理情况单独表示 |
| `expired` | 超过启动期限且从未开始 |
| `unknown` | 提交可能发生但无法确认，禁止自动重试或回滚 |

传输取消可以进入 `cancelled`；进入 `committing` 后使用独立、有界的提交上下文，客户端断线或取消不能将实际成功覆盖成取消。取消请求返回“提交中/不能保证停止”及状态地址；提交超时或关闭异常由实际证据判定 `unknown`。服务退出也遵守该边界。

远程已明确确认提交、但本地终态持久化失败时，当前进程报告“已提交，状态持久化异常”，不能改报普通失败；若随后重启只能读到提交意图，则按 `unknown` 恢复。`unknown` 目标保留写入阻断，重启后从日志重建，核验处理前不接受覆盖该目标的新上传。只读核验可给出内容是否匹配的证据，不自动声称能恢复原操作的确定执行历史。

`requestID` 是客户端生成的任务创建幂等键，与 JSON-RPC 请求 ID 区分。相同认证域、`requestID` 和参数摘要返回已有任务；同键不同参数拒绝。查询已有任务不再次执行副作用。审批继续请求沿用该键和参数，未完成审批不能因重试获得授权。

准备响应丢失时，仅对仍为 `ready` 的原任务重发新任务凭证，并原子撤销旧凭证，不延长启动期限；已经启动的任务只返回状态，不再次开放数据入口。取消及终态查询幂等；不承诺跨服务和远程文件系统的 exactly-once 提交。

错误和警告诊断先归一化为有效 UTF-8，再按字符边界截断至最多 4096 字节，确保 JSON 写入与重载后的字节限制一致。

任务管理器使用带版本的本地元数据日志，目录 `0700`、文件 `0600`，单进程独占，并使用可靠的原子写入/同步顺序。不引入数据库或通用任务队列。记录任务 ID、参数摘要、已解析目标身份、目标/临时路径、必要大小/摘要、状态转换和清理结果；不记录共享 Token、任务凭证明文、SSH 密码或文件内容。任务凭证摘要和最小查询记录按有界保留策略处理。

重启不恢复数据流，也不自动重新提交。`ready` 失效；已知提交前中断的任务标记失败并清理；遗留 `committing` 标记 `unknown`。保留已确认终态。恢复检查不能因文件大小相同就认定成功，也不能在结果不明时删除目标文件。若需要人工核验，应展示目标身份、路径、预期摘要和阶段。

清理只操作日志明确归属的临时文件，禁止扫描匹配后缀后批量删除。新清理上下文和 SFTP 通道具有独立超时；目标不可达或身份发生变化时记录 `cleanup_pending`，限次重试并提供可见结果。正常终态按期限回收，不确定结果或未完成清理的元数据不得被静默丢弃；总量达到上限时拒绝新任务。

提供本地恢复维护入口，与运行中的服务互斥持有元数据锁，只能在服务停止后执行。默认只读展示未知结果、目标当前内容核验和残留文件；显式操作分别用于清理已确认归属的临时文件、记录人工核验结论和解除目标写入阻断。解除阻断不将历史 `unknown` 伪造为成功，也不写入或删除最终目标文件；后续上传仍需新任务及对应授权。人工确认和清理结果写入审计，再按保留期限回收记录。维护入口是首期恢复能力，不要求客户端为正常文件传输安装辅助程序。

## 8. 超时、资源与关闭

以下为实现默认值，部署前可根据资源预算调整，不允许通过零值意外关闭限制：

| 限制 | 初始值 |
| --- | --- |
| HTTP 请求头读取 | 10 秒 |
| MCP JSON 请求体 | 4 MiB；与文件数据路由分离 |
| 普通 MCP 工具调用 | 5 分钟上限；更短的工具期限优先 |
| 审批挑战 | 2 分钟 |
| 传输启动期限 | 5 分钟 |
| 文件流无进展期限 | 60 秒 |
| 单次文件传输总时限 | 2 小时 |
| 单文件上限 | 10 GiB |
| 传输并发 | 总计 4，每个已解析目标 2 |
| 待启动任务/元数据记录 | 256 / 4096 |
| 正常终态保留 | 24 小时 |
| 上传提交/单次清理期限 | 30 秒 / 10 秒 |
| 服务关闭期限 | 45 秒 |

普通 HTTP 请求和工具执行分别持有有界额度，断开 POST 不能释放仍在执行的工具额度。认证后的 JSON-RPC 回复和有效取消通知共用独立控制额度，每类最多 `max_requests`；请求体分类使用同样有界的短时通道，受 4 MiB 和读取期限约束。控制额度只接受不包含 method 且具有 id 与 result/error 的回复，或不含顶层 id/result/error、方法为 `notifications/cancelled` 且参数含有效字符串/整数 requestId 与可选字符串 reason 的取消通知。其他消息仍走普通额度，SDK 继续校验会话、回复 ID 和取消目标。超额立即返回可识别的繁忙错误，不使用无界排队。全局并发额度、任务状态和目标锁的获取顺序固定；数据传输不持有管理器全局互斥锁。

固定大小的应用层缓冲区配合有界 SFTP 请求窗口，内存随并发而非文件大小增长。对 HTTP 文件路由使用精确长度限制，支持有界读取，不继承 MCP JSON 的 4 MiB 限制。网络读写有 Deadline；SSE 和文件流使用可刷新的写入期限及总生命周期限制，不套用会错误截断所有长连接的统一短 `WriteTimeout`。

下载无请求体时清除请求体读取 Deadline，避免 net/http 后台断连检测误取消健康下载。流空闲期限通过进度续期的子上下文同时约束上传领取后的元数据检查、SFTP 和 HTTP；完成或取消时回收计时工作协程，进入提交前停止流计时器，保留独立提交期限。Python 客户端的绝对期限主动中断响应读取，覆盖持续滴流、响应头和关闭型连接，不依赖单次 socket timeout。

每项任务拥有独立 SFTP 通道。现有 v1 客户端的 OPEN 不支持创建权限，私有上传使用额外的串行通道及固定版本 `github.com/pkg/sftp/v2 v2.0.0-alpha2` 的公开报文编解码，仅处理 INIT/OPEN/WRITE/CLOSE；不使用其客户端调度器。报文有界，通道设置、取消和关闭复用已有 SSH 生命周期，元数据与重命名保持现有 v1 语义。取消优先关闭本任务资源；底层若必须关闭共享 SSH 连接才能解除阻塞，应将受影响任务标为传输错误并触发后续连接重建，不自动重放工具或写入。保留这一影响范围，不承诺绝对故障隔离。

关闭顺序：停止接受新任务和数据启动；取消提交前传输；限时完成或判定提交阶段；使用新上下文清理；关闭 MCP 会话和 HTTP 活跃连接；等待工作协程；关闭 SSH 连接器并汇总错误。关闭超时应显式关闭剩余网络连接，不能仅等待 `http.Server.Shutdown`。
