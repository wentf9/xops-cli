# 凭据零配置体验设计

状态：决策已确认，工作分支已实现，待最终平台验收和发布。本文记录发布前体验调整，不代表当前二进制行为。历史 ADR 保留原状；下述体验决策取代旧方案中的默认不保存、显式初始化和手动升级要求，不修改离线库 v1 格式契约。

## 目标与已确认决策

恢复“下载二进制即可连接，输入一次后自动记住”的使用方式，优先保证 Linux、Windows、macOS 的兼容性。

| 项目 | 确认行为 |
| --- | --- |
| 默认后端 | 直接使用 encrypted-file 与 key-file，不探测系统凭据库来选择默认值 |
| 高级配置 | system、pass、helper 等仅由用户手动选择；已有显式选择保持不变 |
| 初始化 | 首次需要持久化时自动准备配置、目录、离线库和 key-file，无需 init 命令 |
| 密钥文件 | 新库所需文件不存在时生成，存在时验证并复用；不覆盖无效、不可读或不匹配的文件 |
| 保存范围 | 登录密码、sudo/su 密码和私钥解锁口令默认保存，按用途独立存储；OTP 等一次性输入不保存 |
| 用户控制 | 提供单次不保存及全局关闭保存；具体参数名称在实施时确定，不在此虚构可执行选项 |
| 自动升级 | 旧配置自动迁移，复制、读回校验并确认后切换引用，保留旧配置和 secret.key |

默认密钥和密文均在本机，保护依赖本机账户和文件权限；同时取得两者的人可以解密。主口令及其他后端为高级选择。目录位置、权限和恢复材料必须在最终用户指南说明。

已有库丢失密钥属于恢复故障，不能通过生成新密钥伪装为初始化成功。自动生成仅适用于可确认的新库初始化；中断重试复用已生成材料，不能覆盖原库。

## 连接、验证与保存

首次交互：确认主机指纹 → 输入认证材料 → 验证成功 → 自动保存 → 后续连接自动读取。保存不成为连接成功的前提；首次保存可给简短说明，日常连接不增加后端选择步骤。

| 事件 | 行为 |
| --- | --- |
| 保存失败但连接已成功 | 保持连接，仅提示密码/口令未保存，下次可能需要输入 |
| 已保存凭据无法读取 | 交互入口允许临时输入；不覆盖损坏库和密钥，不静默切换后端 |
| 服务器明确拒绝密码认证 | 允许交互重输；新密码认证成功后更新，失败保留原记录 |
| 私钥解锁失败 | 允许交互重输；成功解锁对应私钥后才保存或更新其口令 |
| sudo/su 验证失败 | 使用提权交互流程；仅在对应提权验证成功后保存，不覆盖登录密码 |
| 网络故障、超时、指纹异常 | 返回相应错误，不据此更新密码或触发密码失效重试 |
| 无人值守缺少可读凭据 | 明确报错，不等待交互输入 |

不能仅凭 SSH 最终连接成功保存私钥口令或输入密码：连接可能经 agent、其他密钥或其他认证方法完成，保存必须关联实际成功的验证。验证码和 keyboard-interactive 提示不能一概视为可保存密码。取消和超时需结束整个重试流程；重试次数与现有认证策略的衔接列入实施设计。

单次 `--remember never` 或全局 `remember_prompted: never` 禁止连接过程中的自动凭据创建和更新，并禁止当次自动迁移；仍允许读取旧凭据、显式提交凭据表单和执行迁移命令。已由用户确认，自动迁移不得绕过。

## 自动升级与后端迁移

正常使用入口遇到可迁移的旧配置时自动准备目标、复制凭据并读回校验，确认配置持久化成功后切换引用。帮助、补全、doctor、dry-run 等只读路径不得因加载配置而触发写入迁移。各入口触发点需统一实现，不允许只有 SSH 命令升级成功。

迁移失败保持旧配置可用，不以迁移要求阻断原有连接方式。保留旧配置、secret.key 和迁移状态用于恢复；中断后可安全重试，不盲目回滚已提交状态。自动迁移不自动 finalize；用户验证实际连接后显式清理。清理前保留两份凭据，旧存储安全边界仍然存在。

用户手动选择的后端不被默认离线库覆盖。自动迁移只负责旧配置升级，不因已配置后端暂时不可用而转存到离线库。Schema v2 已存在但未显式选择后端的配置如何识别，需在实施前检查现有字段及兼容性，避免覆盖用户主动选择 none 的意愿。

高级用户必须能把自动迁移后的离线凭据再迁移到已配置的其他可写后端，也能迁回离线库。流程为：配置目标 → dry-run → 显式执行 → 读回校验及引用切换 → 验证真实连接 → 单独清理旧材料。失败保留源数据；不把修改默认后端等同于迁移已有引用。

当前 `credential migrate --to <store>` 用于旧配置升级，跨 v2 后端的范围和恢复语义需实现并测试后才能写成已支持操作；离线库 clone 也不能代替任意后端迁移。

## 实施约束

沿用现有凭据服务、不可变引用、事务日志、CAS 和持久化确认，不降低文件权限、链接检查、原子发布和恢复要求。可复用包只返回结构化结果和错误，交互提示由 CLI/TUI 等组合入口负责。不得在配置、日志、参数或错误中输出秘密。

验收范围覆盖 CLI、TUI、SSH、SFTP/SCP、exec、Playbook、MCP 及任务级身份覆盖；按实际交互能力决定是否提示，不能仅凭命令名称判定。实施阶段与验收矩阵见[实施计划](./credential-experience-plan)，用户发布文案见[更新说明草案](./credential-experience-release)。
