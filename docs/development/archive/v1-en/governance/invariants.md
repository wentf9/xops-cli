## 1. Architectural Change Summary (P7 Seven Pillars)

Earlier remediation rounds (P0–P6) fixed individual instances, yet 8 **meta-root-causes (M1–M8)** kept regenerating bugs: safety rules enforced by memory instead of visibility/types (M1), hand-picked cache/scope identity keys (M2), ad-hoc per-caller OS file/lock primitives (M3), string sentinels overloaded for tri-state semantics (M4), bare `bool` security predicates swallowing errors into allow paths (M5), caller-managed resource lifecycles (M6), persistence invariants living in `cmd` instead of the commit boundary (M7), and fragile name-based guards (M8).

P7 enforces five non-negotiable architectural principles—**types as capabilities**, **single implementation enforced by visibility**, **identity keys derived from full structures via reflection**, **zero = deny & error = deny**, and **invariants enforced at the write boundary**—implementing seven pillars (A–G) with zero backward-compatibility shims:

## 2. Non-Negotiable Architectural Invariants

### INV-A: Handle-First Filesystem & ACL Kernel (`core/fsx`, `core/winsec`)

- **`INV-A1` (No Stat-Then-Open)**: Outside `core/fsx`, direct calls to `os.Open`, `os.OpenFile`, `os.ReadFile`, `os.Remove`, `os.RemoveAll`, `syscall.Flock`/`unix.Flock`, and `windows.GetNamedSecurityInfo`/`SetNamedSecurityInfo` are forbidden (`.golangci.yml:forbidigo`). Regular reads use `fsx.OpenRegular` / `fsx.ReadAllBounded` / `fsx.OpenRegularUnbounded`; exclusive file creation uses `fsx.CreateExclusive` (Unix `O_CREAT|O_EXCL|O_NOFOLLOW` `0600`; Windows `CREATE_NEW` with an Owner-Only Security Descriptor at creation time, eliminating post-create ACL windows).
- **`INV-A2` (Post-Lock Handle Identity Verification)**: `fsx.OpenLocked` / `OpenLockedContext` acquires `flock` / `LockFileEx`, verifies `os.SameFile(handleStat, lstat(path))` (retrying up to a bounded limit on mismatch), and performs all subsequent I/O solely through the locked handle.
- **`INV-A3` (`SocketSlot` Single Ownership & Release Order)**: Control-socket `Bind`, `ReplaceStale`, and `Release` execute under the same directory lock (`core/fsx/socket_slot.go`, including real file locking on Windows). `Release` strictly follows `lock dir -> SameFile -> unlink -> close listener -> unlock dir` so live sockets are never unlinked by stale owners.
- **`INV-A4` (Windows Handle-Based DACLs & Long Paths)**: `core/winsec` performs DACL inspection/mutation via `FILE_FLAG_OPEN_REPARSE_POINT|FILE_FLAG_BACKUP_SEMANTICS` handles (`GetSecurityInfo`/`SetSecurityInfo`) with ancestor reparse-point checks. `OpenObjectHandleNoFollow`, `EnsureOwnerOnlyDirectory`, `GetFileAttributesNoFollow`, and `core/mcp/transfer/journal_windows.go:replaceJournalFile` normalize paths `>= 248` UTF-16 code units to `\\?\` / `\\?\UNC\...`.
- **`INV-A5` (Zero-Value Limits/LockMode Fail Closed)**: `fsx.Limits{}` (`MaxBytes == 0`) and `fsx.LockMode(0)` return `fsx.ErrInvalidLimit` / `fsx.ErrInvalidLockMode`.

### INV-B: Typed Transfer & Path Safety (`core/sftp`, `cmd/scp.go`, `cmd/sftpshell`)

- **`INV-B1` (Single Typed Download Facade)**: External callers download solely through `(*sftp.Client).Download(ctx, RemotePath, LocalDest, DownloadOptions)`. Remote paths are constructed via `sftp.ParseRemotePath`, directory entries via `sftp.ReadValidatedDir` / `(*Client).ReadDir` (`core/sftp/readdir.go`, the sole caller of raw `*pkgsftp.Client.ReadDir`), and `filepath.Base` on remote paths is forbidden in transfer code (`.golangci.yml:forbidigo`).
- **`INV-B2` (Symlink Download Policy `(b)` & Fold-Collision Fail-Closed)**: Only relative POSIX symlinks whose resolved traversal stays strictly inside `localRoot` (`depth >= 0`) are preserved; absolute targets, escaping or chained-escape symlinks, NFC/NFD + `cases.Fold`/`SimpleFold` sibling collisions, and `os.ModeIrregular` entries fail closed with `sftp.ErrUnsafeDownloadSymlink`.
- **`INV-B3` (Single Component Validator & Safe Staging)**: Windows reserved device names (including superscript `COM¹–LPT³`), NTFS ADS (`:$DATA`), trailing dots/spaces, and control chars are validated exclusively by `core/fsx/validate.go:ValidateLocalComponent`. Download staging files use `0600` pre-write permissions with `.Perm()` stripping setuid/setgid/sticky bits; negative remote `Size() < 0` fails closed with `sftp.ErrInvalidRemoteSize`.
- **`INV-B4` (Exact-Target Upload & `Lstat` Dangling-Symlink Overwrite Checks)**: `cmd/scp.go` and `cmd/sftpshell/shell.go` expand container directories (`ParseRemoteUploadTarget`) at most once, check existing targets with `c.Lstat` (catching dangling symlinks under `--no-clobber`/overwrite prompts), reject file-over-directory/directory-symlink mismatches, and invoke `(*sftp.Client).UploadExact` to prevent nested re-expansion inside `core/sftp`.

### INV-C: SSH Pool, Multiplexing, Channels & Host Keys (`core/ssh`, `internal/sshenv`)

- **`INV-C1` (`NewClientConfig` Construction & Full Merkle `HopDigest`)**: Production Go code must construct `core/ssh.ClientConfig` solely via `core/ssh/types_api.go:NewClientConfig` (`TestP7_ClientConfigConstructedViaNewClientConfigOnly`), with raw `DigestClientConfig` parity. Every field of `ClientConfig`, `Options`, and `ControlConfig` must declare `digest:"include"` or `digest:"exclude,reason=..."` (`TestHopDigest_StructTagCompleteness`); `HopDigest` recursively hashes parent hop digests so upstream mutations always invalidate downstream keys.
- **`INV-C2` (Parent-Generation CAS, Owned Keepalive & Synchronous Eviction)**: `connPool.Publish(key, next, expectParent)` verifies under lock that `next.parent` is still the active parent generation before publishing, routing displaced clients to `retired` for `CloseAll`. Keepalive is owned exclusively by `PooledClient` and stops on retire/close. `(*Client).Close()` / `Interrupt()` synchronously detach from pool maps and fire `triggerEvictHook` to tear down attached `MuxServer`s. Multi-hop reuse validates every intermediate hop via `probeCachedIntermediateHops` + `SnapshotChain`.
- **`INV-C3` (Bounded `proxyChanConn` Close & Deadlock-Free Escalation)**: `proxyChanConn.Close` waits up to `90ms` (`defaultProxyChanCloseGrace`) before escalating via `detachAndAbortRoot`. Active descendants are claimed by removal from `p.active`; retired descendants use single-winner `retiredAborted.CompareAndSwap(false, true)`; `closeBatchDescendantsSkipping` skips children with `child.hopConn.isClosing() == true` (while still stopping keepalive and firing `triggerEvictHook`), eliminating mutual `closeOnce.Do` AB-BA deadlocks without disturbing healthy bastions.
- **`INV-C4` (`MuxServer` Shutdown Order & Bounded Outbound Ops)**: `(*MuxServer).Shutdown` executes strictly as `beforeTransportClose -> release SocketSlot -> evictFromPool -> closeTransportBounded -> drainTrackedStreams`; `MUX_C_PROXY` wraps `physicalSSHConn`/`sshActivityConn`; agent forwarding uses ref-counted `agentForwardEpoch`; outbound `CloseWrite`/`Close`/`Reply` operations are bounded and decoupled from inbound pump drains.
- **`INV-C5` (Single Shared-Locked `O_NOFOLLOW` `knownHostsDB` Snapshot)**: `(*Connector).getHostKeyOptionsWithState` reuses the single `*knownHostsDB` built under `knownHostsFileMutex` + `fsx.OpenLocked(..., LockShared, false, 0)` across both `HostKeyCallback` and `HostKeyAlgorithms` (including `StrictHostKeyChecking=no`). Custom `UserKnownHostsFile` opens directly via `OpenLocked` (skipping `os.ErrNotExist`, failing closed on symlinks/directories/special files) and never uses `FollowSymlinks()` or Windows system-SSH ACL validators.
- **`INV-C6` (Unconnected Client Nil Safety & Outcome Semantics)**: `*Client`, `*PooledClient`, `SSHProxyDialer`, and `getOrCreateAgentRouter` reject `Client == nil || Client.Conn == nil` and `ctx == nil` without panicking. Remote execution distinguishes `ExecutionNotStarted`, `ExecutionCompleted`, and `ExecutionUnknown`; unknown outcomes never auto-retry; `*OutputError` wrapping is deduplicated.

### INV-D: Option Algebra, Provenance & Cross-Plane Resolution (`core/ssh`, `pkg/adapter`, `cmd/ssh*`)

- **`INV-D1` (Single Parser & Tri-State Monoid Algebra)**: CLI `-o`, OpenSSH config, and YAML all parse via `core/ssh/option_parser.go:ParseOption`. `PathList` (`Unset | Disabled | Set`), `AlgoPolicy` (fail-closed on bare `+`/`-`/`^` or invalid modifiers at parse time), two-slot `ProxySetting`, and `ControlSetting` obey associativity, identity, and absorption laws (verified by property & fuzz suites). `IdentityFile=none` yields `PathList.IsDisabled()`, preventing default `~/.ssh/id_*` fallback or `password` -> `auto` promotion.
- **`INV-D2` (Explicit `NodeProvenance` Isolation)**: `pkg/config/provenance.go:NodeProvenance` classifies connections as `ProvenanceSavedManaged`, `ProvenanceOpenSSHVirtual`, `ProvenanceOpenSSHDerived`, or `ProvenanceAdHocPending`:
  - Only genuine OpenSSH `Host`-derived sessions (`IsOpenSSHNodeID(baseNodeID)` + non-empty `OpenSSHAlias` + `SSHOptions == nil`) receive `ProvenanceOpenSSHDerived`.
  - Saved-node overrides (`-l`/`-p`/`-o HostName`/`CanonicalizeHostname`/`NodeOpenSSHOrigin`) and raw ad-hoc `user@ip` sessions **remain `ProvenanceAdHocPending`**, are **never rewritten to `"openssh:..."`** across dial, `-f` pre-fork, `-O` control plane, or `ControlPersist` handoff (`cmd/ssh.go` + `cmd/mux_daemon_spec.go`), and always enforce `filterNonVirtualTier4Options` plus `(Host, Port)` endpoint scoping.
- **`INV-D3` (Four-Plane `SessionAuth` & Policy Parity)**: `(*SSHAdapter).Resolve` is the sole 4-tier policy exit (`Tier 1 CLI > Tier 2 Saved Node > Tier 3 Global > Tier 4 OpenSSH`). `SessionAuth.{HostName,User,Port,ProxyJump,OriginalHost,CanonicalHost}` is propagated identically across dial, `-f` pre-fork (`buildProxyCommandPathChecker`), `-O` control plane (`check`/`exit`/`stop`/`forward`/`cancel`/`proxy`), and `ControlPersist` handoff. When `CanonicalizeHostname` triggers with active CLI `-o HostName`, `applyHostnameCanonicalization` updates `o.cliHostName`/`o.HostName` in place while preserving `OriginalHost` (`%n`).
- **`INV-D4` (Alias Parity & Whitelist Token Encoding)**: `Node.Alias` and `Host.Alias` behave identically in forward resolution and reverse callbacks (`BatchMode`, `Remember`, `UpdateAuth`, `DisableSessionControlSharing`, `OTP`/`ChallengeRule`); `SendEnv -PATTERN` strips prior patterns at merge time; `RemoteCommand`/`ProxyCommand`/`LocalCommand` share one whitelist token encoder.

### INV-E: Fail-Closed Verdicts & Two-Phase MCP Guardrail (`core/verdict`, `core/mcp/**`, `internal/mcphost`)

- **`INV-E1` (Zero = Deny, Error = Deny)**: `core/verdict.Verdict` defaults to `Deny` (`0`), and `verdict.Decide` collapses any non-nil error to `Deny`. Repo-wide predicates may not swallow local errors behind bare `bool` (`TestP7_SecurityPredicateAnalyzer_ZeroBareBoolErrSwallow`). `suspend_unix.go` implements the complete POSIX orphaned process group predicate and denies on any `Getsid`/`Getpgid` failure.
- **`INV-E2` (Typed Tier-4 Endpoint Scoping)**: Tier-4 matching and fallback key construction use `ssh.Endpoint` (normalized host + `[1..65535]` port; zero value is invalid and never equals anything), preventing port-blind address matching.
- **`INV-E3` (Deterministic Policy & ProtectedPaths)**: `core/mcp/guardrail/glob.go:matchGuardrailGlob` provides OS-independent $O(|P|\cdot|S|)$ UTF-8 rune matching (`*`/`?` match `/`, `\`, `\n`); `NodeOverrides` evaluates all matching entries with strictest-wins (`min` `RiskLevel`); `ProtectedPaths` evaluates POSIX literal-backslash paths OR-ed with normalized Win32 drive/device/UNC/ADS/trailing-dot-space forms; `WithGuardrail` and `Authorize` `switch decision` blocks must terminate with an explicit fail-closed `default: return`.
- **`INV-E4` (Frozen-Snapshot Execution & POSIX Bourne Validation)**: `internal/mcphost` `ProbeExecution`, `Run`, `OpenPTY`, and file/transfer paths validate `permit.Binding().Validate(view)` and dial via `connectPlan` against the admitted frozen `providerKey{}` snapshot. `gui` participates in `prepareAndResolveExecution` probing and `{Input, Execution, PlanDigest}` binding. `RequirePOSIX` and `Filesystem` enforce `ports.ValidatePOSIXBournePlan` in both `sshexec.Backend.Run` and `mcphost.backend.Run` (requiring `server+LaunchPOSIX` or `sh`/`bash`/`zsh` over a known non-`LaunchUnknown` dialect, never `LaunchDialect` alone).
- **`INV-E5` (Two-Phase Canonical Inspection, Envelope Anti-Replay & Zero Orphan Audits)**:
  - `file` (`read`/`write`/`patch`/`stat`) and stdio `transfer` (`push`/`pull`) run a two-phase `lexical precheck -> ports.Inspect canonicalization -> canonical authorization -> ports.Execute re-verification with pinned canonical source & exact destination (UploadExact / LocalDestFromTarget)` pipeline, including `RecursivePaths` descendant `ProtectedPaths` elevation for directory transfers.
  - Pending two-step challenges (`pendingApproval`) bind the pre-inspection request envelope (`WithRequestEnvelope`: `ToolName`/`Action`/`NodeID`/`Scope`/`SnapshotDigest`/raw input/policy); cross-session/tool/node/path replays and declined/malformed `InputResponses` reject and audit `"denied"` prior to dialing SSH; failed Round-2 inspections call `InvalidatePendingApproval` to close SFTP error oracles.
  - `canonicalScopeEscalated` re-prompts and retires Round-1 tokens without writing `"authorized"` on risk escalation, policy tightening, unprotected->protected transitions, and `Protected-A -> Protected-B` canonical symlink redirects (`diffScopePaths` hitting `HasProtectedPath`); every `"authorized"` `opID` is closed with terminal `"executed"` or `"error"` across all outcomes.
  - `requestToolApproval` validates/consumes carried `RequestState`/`InputResponses` before `< 2026-07-28` and `applyFallback` early returns.
  - HTTP `transfer` (`status`/`cancel`) and stdio `tunnel` (`status`/`stop`, using read-only non-pruning `Manager.Inspect`) route unconditionally through `r.resolve -> guardrail.Authorize -> r.enter` before exposing `not_found` or mutating state, recording `RecordAuthorizedContext` to preserve `AuditEntry.Binding`.

### INV-F: Config Write-Boundary Invariants, Scoped Leases & Credential Atomicity (`pkg/config`, `pkg/credential`, `cmd/host`, `pkg/tui`)

- **`INV-F1` (Full-Graph Validation at Load & Commit)**: `pkg/config.Repository` enforces `ValidateGraph` and `ValidateSavedNodeJumpCycleWithOpenSSH` on load and every write (`NewRepository`, `ImportOpenSSHHostsContext`, `cmd/init`, `host add/edit/load`, TUI, pending confirmation, and `doctor --fix`): rejecting cross-namespace `ProxyJump` cycles, enforcing single `ValidateNodeAlias`, requiring `PassphraseRef != nil => KeyFingerprint != ""` and valid fingerprint characters, and enforcing `StoreID` existence in `cfg.Credential.Stores` across all 5 credential ref fields in Schema v2. Non-conforming `xops_config.yaml` fails closed on load and is repaired explicitly via locked CAS `xops config doctor --fix`.
- **`INV-F2` (No Pre-Dial Persistence & Scoped Pending Leases)**: `cmd/{ssh,scp,exec,sftp}` never write back saved nodes prior to dialing. Unpersisted session changes live inside `WithPendingNode(ctx, req, func(PendingLease) error)`, auto-discarding on any unconfirmed return/cancel/panic while preserving `entry.isUpdate` across unrelated commits; `FinalizePendingConnection` confirms uniformly across fresh handshakes, pool hits, and ControlMaster reuse.
- **`INV-F3` (Vault-First Creation & 5-Location Ref Accounting)**: `NodeCredentialCreate` and `IdentityCredentialCreate` write and constant-time-verify vault secrets before committing `config.yaml` (leaving zero dangling refs on locked/failing vaults and compensating only newly created refs on CAS conflict). Cross-kind credential rotations and deletions run inside `credential.Service.DeleteAssets` gated by disk-reloaded 5-location `CheckRefUnreferenced` / `ConfigurationReferencesCredentialStore`. `Applied=true, Durable=false` (`DurabilityError`) is never retried or rolled back destructively.
- **`INV-F4` (Hybrid Auth Preservation, Aliased-Host Isolation & Immutable Templates)**: `config.IsHybridAuthType` (`auto`/`otp`/`keyboard-interactive`) preserves hybrid `AuthType` and orthogonal credential fields across CLI/TUI/pending updates and `host import` `verificationBundle`. `AllocateNodeHostRef` and `ensureMatchingHost` never hijack aliased `Host` records (`host.Alias = nil` on shared fork). `xops host add/edit -I/--identity` rejects empty template names and conflicts with `--user`/`--key`/inline `user@`, and `host add -I` invokes `CreateNodeContext` directly without touching template vault secrets. `PrivateKeyFingerprint` and `cred set --passphrase` reject `"none"`, `%` templates, `${ENV}`, and unexpanded `~user` via `ssh.ParseIdentityPathSetting`.
