# 凭据体验更新说明草案

状态：工作分支已实现，待最终平台验收、待发布。以下内容不代表已发布版本。

## 下载即用，默认记住凭据

目标版本默认使用内置离线凭据库和自动生成的 key-file，无需配置系统凭据库或先运行初始化命令。登录密码、sudo/su 密码和私钥解锁口令在对应验证成功后自动保存；验证码不保存。支持单次不保存和全局关闭保存，使用 `--remember never` 或全局 `remember_prompted: never` 可关闭自动保存及自动迁移。

保存失败不终止已成功的连接，会提示本次凭据未保存。读取失败时，交互连接可以临时重输；无人值守执行返回错误。默认方案依赖本机权限，同时获得 key-file 和密文的人可以解密。

## 升级会自动迁移旧凭据

正常使用入口检测到旧配置后自动准备离线库，复制并校验凭据，再切换配置引用；不需要先手动执行迁移命令。失败时保留旧配置可用性，已有手动后端选择不被覆盖。

启动自动迁移始终遵守非交互边界。MCP、Playbook 等启动前不会为了迁移弹出解锁提示；后端需要交互时提示迁移未完成，保留原配置，仍支持显式迁移。

旧配置、secret.key 和迁移恢复材料会保留，不自动删除。验证 SSH、SFTP、exec、提权及自动化入口后，再按照最终恢复/清理说明显式完成清理；清理前仍保留旧存储的安全边界。只读命令不触发自动迁移。

## 想体验其他后端

在现有配置中添加 system、pass 或 helper 目标后，可以显式迁移已有 v2 凭据。先运行 `xops credential migrate --dry-run --to system`，再运行 `xops credential migrate --to system`。全部读回验证成功后才切换引用和默认库，保存策略不变。dry-run 不保证写入成功。

返回离线库使用 `xops credential migrate --dry-run --to file` 和 `xops credential migrate --to file`。已有 key-file 直接复用。中断后重跑原命令；配置并发修改时拒绝覆盖，可用 `--restart` 归档旧计划后按当前配置重新规划。

源凭据和配置备份全部保留；`finalize-migration` 仅用于清理 v1 旧材料，不清理后端源凭据或 v2 备份。完整配置、恢复和返回示例见[迁移指南](../guide/migration)。本地往返与故障注入已验证，系统后端的实际可用性取决于本机服务；最终六平台验收仍待执行。
