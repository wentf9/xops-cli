- 关联：[ADR-0001](0001-credential-persistence-backends.md)

- 实施设计：[详细设计](../design/offline-encrypted-credential-store.md)与[格式／协议规格](../design/offline-encrypted-credential-store-format.md)（v1 已冻结；正文早期验收要求的完成证据见冻结记录）

## 问题

pass、system 和外部 helper 都可能依赖目标运行环境提供额外组件。内网服务器只有
一个 XOps 二进制时，需要可直接使用的持久化后端，避免为了保存密码恢复旧版
“配置密文与自动生成的 secret.key 放在一起”的默认行为。

## 建议决策

增加显式配置的 `encrypted-file` 后端，密码学和文件访问逻辑编入 XOps 二进制。
运行时不需要 pass、GPG、OpenSSL、桌面会话、系统守护进程或联网下载。
继续使用 Schema v2 的 StoreID/ItemID 引用、CredentialService 和恢复 journal。

普通新安装仍默认 none。不探测失败后自动切换，不自动迁移现有 Store，不把解锁
材料写进 YAML、argv、日志或 journal。该后端是新的独立凭据库，不是 legacy-file。

## 解锁方式

| 模式 | 适用场景 | 代价及保护边界 |
| --- | --- | --- |
| 主口令（建议默认） | 交互运维；只有单个二进制 | 每次进程首次访问时解锁一次；主口令不落盘，目录备份被复制后仍需猜解口令 |
| 独立密钥文件（显式选择） | CI/MCP、定时任务、无人值守 | 密钥由用户独立供应；必须与密文分开管理，密文与密钥同时被复制时无法保密 |

不得用机器 ID、主机名、MAC 地址、用户名等公开信息派生密钥，也不提供默认口令。
独立密钥文件不能自动放进配置目录；推荐独立只读挂载或部署系统注入。
同一用户/root 已能读取运行进程、主口令或密钥文件时，不在本方案保护范围内。

主口令长度和强度直接影响离线猜解难度；KDF 不能让弱口令变得安全。
丢失主口令/独立密钥且没有备份时，库中的凭据不能恢复。

## 文件与密码学设计

使用版本化的封套加密，不自创密码算法：

- 初始化时生成随机 256-bit 数据密钥 DEK 和随机 vault ID。
- 主口令通过 Argon2id 和每库随机 salt 派生包裹密钥；首版固定为 64 MiB、3 次、
  并行度 1、输出 32 字节，读取与写入只接受这一组合，不开放自由调参。
  文件内 KDF 参数先做严格白名单检查，再分配工作内存，防止恶意头部制造资源耗尽；
  资源不足失败关闭，不自动降低参数。具体内存策略见下文已确认的 KDF 规格决策。
- 密钥文件模式使用用户独立提供的 32 字节随机密钥，经标准 HKDF 域分离后用于包裹。
- AES-256-GCM 包裹 DEK；每条秘密独立使用 AEAD 加密，随机 nonce，AAD 绑定
  格式版本、加密套件标识、数据密钥代次、vault ID、StoreID、ItemID。
  禁止跨条目、跨库或跨代次直接替换密文而仍解密成功。
- 同一 AEAD 密钥下不得复用 nonce。格式规范必须固定 nonce/tag 长度，禁止截短 tag；
  首版每个 DEK 最多执行 2^20 次条目加密，达到上限后拒绝新加密，须显式换 DEK
  才能继续；具体碰撞预算和预警规则见下文已确认的使用预算决策。
  重试只可复用完全相同的既有密文，重新加密必须分配新 nonce；随机源失败直接报错。
  多进程写入必须遵守相同限制，不能仅依赖各进程自己的计数。
- 每个 ItemID 一个加密文件，只解密请求的条目。元数据文件保存 KDF 参数、salt、
  加密 DEK 等非明文密钥材料，不保存可直接使用的解密密钥。
- 修改主口令只重新包裹 DEK；需要换掉已泄露的 DEK 时必须另做全库重加密，不能
  把“改口令”描述成撤销旧备份或已泄露凭据的能力。

AEAD 能检测密文修改或错配，但不能阻止整个库被删除，也不能单独检测整个库被
回滚成旧备份。缺失条目按 not-found 失败关闭；备份、回滚与凭据撤销边界须写入文档。

采用成熟算法不等于实现已经安全。算法选择、格式、密钥生命周期、文件事务和部署
方式都必须通过下述验收；不得以一次加解密往返测试替代安全评估。

## 密码学版本与降级防护

容器格式、密钥包裹套件、条目加密套件分别版本化，不能用一个总版本号隐含全部语义：

- 容器格式版本负责字段布局、长度限制和编码规则。
- 包裹套件 ID 唯一确定 KDF、派生密钥长度、域分离规则和包裹 AEAD；具体参数
  （含 salt）显式编码。主口令模式与独立密钥文件模式使用不同 ID。
- 条目套件 ID 唯一确定数据 AEAD、密钥长度、nonce/tag 长度及 AAD 编码；每条记录
  标注数据密钥代次，不能把新旧数据密钥混用。
- 头部中的这些标识、KDF 参数、salt、vault ID、StoreID 和密钥代次必须纳入包裹
  AEAD 的认证数据；条目头部的相关标识也必须由条目 AEAD 认证。格式规范固定
  唯一字节编码，避免同一语义多种编码、字段遗漏或重解释造成认证绕过。

实现只接受明确审核过的固定套件集合，不允许用户任意组合算法、动态加载密码插件，
也不允许由库文件指定可执行命令。解析认证前必须先检查长度、版本、套件白名单和
KDF 参数上下限；认证成功前不得把头部信息视为可信。

未知版本、未知套件、非法参数、认证失败均失败关闭。不得在失败后尝试其他 KDF、
旧格式、弱参数或 legacy-file。正常创建与写入使用当前推荐套件；允许读取旧套件
不代表允许继续向旧代次追加写入。

最低安全策略由当前程序发布版本及受信任的部署策略决定，不能由库内字段自行降低。
格式标识的认证只能防止篡改，不能证明整个库是最新版本；离线环境没有外部可信状态
时，不宣称能够阻止完整旧备份回滚。将来若需要抗回滚保证，应另行设计可信的外部
版本锚点，而不是依赖与密文一起可被回滚的本地计数文件。

## 密码学升级与泄露处置

| 触发条件 | 必须执行的操作 | 不能保证的事情 |
| --- | --- | --- |
| KDF 参数需要加强、无泄露迹象 | 验证旧解锁材料，以新 salt/参数重新包裹同一 DEK | 旧备份仍使用旧参数 |
| KDF 或包裹算法需要替换、DEK 未疑似泄露 | 使用旧方案解锁，以新套件重新包裹 DEK | 不提升旧副本的安全性 |
| 条目 AEAD 需要替换、密钥使用量到限 | 生成新 DEK，逐条用新套件和新 nonce 重加密 | 不撤销攻击者已取得的旧副本 |
| 主口令、独立密钥或 DEK 疑似泄露 | 更新解锁材料、生成新 DEK、全库重加密，并评估轮换实际凭据 | 单纯改口令或重加密不能收回已泄露的服务器密码 |
| 旧算法已可实际破解 | 尽快升级，并将相关旧密文视为潜在明文泄露来源，按暴露范围轮换实际凭据 | 无法通过更新软件让已外泄备份重新保密 |

改口令、提高 KDF 成本和替换数据加密算法是不同操作，命令及帮助必须明确区分。
若旧密码或密钥可能已泄露，不得把只重新包裹 DEK 作为充分的安全修复。
删除本机旧文件也不能保证擦除 SSD、快照、远端备份或攻击者持有的副本。

升级采用显式、可恢复的流程，不能在普通 Get 或配置加载中静默转换全库：

1. 检查源套件的读取策略和目标套件的写入策略，取得解锁材料并预检空间、权限。
2. 在独立的新代次中写出完整目标库；需要换数据 AEAD 时生成新的 DEK 和随机 nonce。
   普通重加密保持 StoreID/ItemID 逻辑引用不变，避免改写所有使用该凭据的配置。
3. 固定源代次并协调写入：首版从构建目标库前到发布完成或失败全程持有可取消等待的
   库级独占锁，禁止升级丢失并发 Put/Delete。上述目标构建必须在取得锁并重新校验
   源修订后执行；不得把整个加密升级放在配置 Repository 或 Registry 的锁中。
4. 每条写入都读回、认证并比较明文，校验目标条目集合与源快照一致；一次只保留
   必要的明文，使用后尽力清零，不在日志中记录秘密或解锁材料。
5. 所有目标文件及必要目录 durable 后，通过经平台验证的原子发布机制切换当前
   代次。读者只能看到一个完整代次，不能依赖替换非空目录实现未经验证的原子切换。
6. 提交后重新打开目标库并验证；新读取必须按发布修订号刷新解锁状态和秘密缓存，
   包括 DEK 不变的重包裹操作，不能继续把旧会话或旧代次缓存当作当前库的有效内容。
7. 用户确认升级结果后，再显式清理旧代次和备份；升级流程不得自动删除唯一可用副本。

升级日志仅记录操作 ID、源/目标格式与代次、进度、完整性/版本标识和阶段，不记录
主口令、DEK、派生密钥或秘密。源库修改、写入失败、空间不足、读回不一致及进程
中断都必须有明确恢复结果。发布已 Applied 但未确认 Durable 时保留新旧代次，返回
耐久性错误，不盲目回滚或重复切换。恢复必须通过与正常读取相同的安全策略检查，
不能借“恢复旧任务”重新启用已禁用的算法。

格式规范必须定义逐阶段状态机、发布标记与锁顺序，并在实现前确定跨平台原子发布
机制。本文的代次协议是强制约束，不能仅采用单代次文件布局而省略升级事务。

## 算法支持与退役策略

每次发布维护明确的套件支持表：推荐写入、兼容只读、仅受限迁移、完全拒绝。
新库使用推荐套件；打开旧库时给出可操作的升级提示，不靠降级继续写入。

常规格式升级应公布兼容窗口、最低可读版本和显式迁移方式。发现严重密码学或实现
漏洞时，可以提前停止普通读取和写入，不受 Schema v1 的两个发布周期约束；两者
是不同的兼容政策。只有安全评估认为仍可操作时才保留受限旧格式导入工具，该工具
必须显式运行、校验输入、限制资源，且不向普通 Store 路径提供弱算法回退。
如果不能提供安全迁移路径，应明确拒绝并提供重新配置/轮换真实凭据的步骤。

发行维护需跟踪密码学标准、所用库的漏洞公告和审计结果，评估是否只是参数升级、
需要算法替换，或必须按凭据泄露处置，并在发布说明中写明影响、升级步骤和备份风险。
AES-256 对当前已知量子攻击具有较大的安全余量，但这不是永久安全保证；未来更换
方案仍走同一套显式升级协议，不因“抗量子”名称省略设计和实现审查。

## 文件持久化约束

已确认的首版布局（具体文件编码仍须在实施规格中落实）：

```text
credentials/offline/
  vault.lock
  CURRENT
  revisions/<vault_revision>/
    vault.meta
    items/<ItemID>.enc
  key-state/<dek_generation>/budget
  transactions/<operationID>/state
```

CURRENT 指向完整发布目录，普通 Put/Delete 修改当前目录，不逐次复制全库。
预算按 DEK 代次独立保存，同 DEK 的多个发布修订共享预算；发布和恢复见下文已确认规格。

目录权限 0700，文件 0600；Windows 还须验证文件 ACL，不能只依赖 chmod 数字。
校验文件类型、大小和路径；拒绝不安全的符号链接/路径穿越，打开与替换需避免
检查后路径被替换的竞争。写入临时文件、文件 sync、原子替换及目录 sync 缺一不可。
由部署者保证所选文件系统可靠提供这些语义，不按文件系统类型拒绝访问。
验收覆盖主流本地文件系统 ext4、XFS、Btrfs，不对 NFS/共享盘及特殊文件系统做专项适配。

Put 对已有同一 ItemID 必须满足幂等重试：同值成功，异值报冲突，不覆盖既有秘密。
删除必须幂等；配置引用已 durable 解除后才由现有事务服务调用删除。
重启恢复不依赖已删除实体还存在，继续支持 asset_delete journal。

## 解锁与进程生命周期

业务调用方注入 `UnlockProvider` 小接口，Store 不直接操作终端。CLI/TUI 负责隐藏
输入并共享可取消的 Prompt Gate。读取节点列表、普通元数据编辑不解锁。
同一进程同一库的并发首次访问只触发一次解锁，等待者可取消，失败后允许重试。

只在进程内保存已解锁的 DEK，不长期保留主口令；CLI 结束或显式关闭时尽力清零。
TUI/MCP 长进程需要有界 idle TTL，锁定时同时清除 DEK 与该库的秘密缓存。
解锁会话与秘密缓存采用独立 TTL，具体默认值、续期和锁定边界见下文已确认的决策 1。
现有 lazyStore 并发构造可能产生多个实例，因此解锁状态必须由明确的进程级会话
对象管理，不能简单放在每个临时 Store 构造对象里。

Argon2id 不支持中途取消。首版复用受控子进程机制，在同一个 XOps 二进制的私有
内部入口执行 KDF；不能用后台 goroutine 超时丢弃结果伪造取消。超时或取消时终止
子进程并等待回收，具体预算与平台取消边界见已确认的决策 6。
解锁材料只经有大小上限的管道传递，不进入 argv。该内部协议需单独定义、测试，
不能未经版本协商向通用 helper v1 响应添加可被第三方误解的解锁动作。

未解锁、非交互缺少主口令或 DEK 包裹认证失败时返回 locked；不存在的库返回
unavailable，不在 Get 时创建新库。可确定的结构损坏、权限拒绝、锁超时分别提供
稳定错误，具体分类见已确认的决策 7；不回显文件载荷，也不把认证失败断言为口令错误。
业务发现 ref 时不得把解锁失败转为“请输入新的服务器密码”。

## 非交互、迁移与 doctor

- 主口令模式未解锁时，MCP/批处理/doctor 不弹终端或 GUI，返回 locked。
- 独立密钥文件模式允许非交互；缺失、权限不安全或密钥错误均失败关闭。
- doctor 不隐式初始化库、不设置默认 Store、不写探测秘密；锁定不是未安装依赖。
- v1 迁移复用现有迁移器，先初始化并可解锁目标库，再写入、读回、提交和验证。
  finalize 只清理旧 v1 材料，不删除新库、主口令包裹信息或独立密钥文件。
- GC 需要解锁才能物理清理条目；未解锁时保留日志并返回未完成，不删除唯一副本。

## 使用方式

以下命令和配置是接口草案，当前二进制不支持：

```yaml
credential:
  default_store: offline
  remember_prompted: ask
  stores:
    offline:
      type: encrypted-file
      path: ./credentials/offline
      unlock: prompt
      unlock_idle_ttl: 5m
      prompt_timeout: 2m
      unlock_timeout: 30s
      timeout: 10s
      cache_ttl: 0s
```

独立密钥模式使用 `unlock: key-file` 与 `key_file: /run/credentials/xops.key`。
只允许配置路径，不允许配置密钥内容。相对路径的基准应统一为配置文件所在目录。

初始化与改主口令分别采用下文已确认的 credential store init 和 rewrap 接口。
初始化拒绝覆盖现有库，改口令验证旧口令并支持中断恢复。

## 待定事项与决策门

以下七项决策已确认，作为实施约束；文末列出的具体规格与验证仍需完成。
决策确认不代表后端已经实现，也不代表格式 v1 和全部对外接口已经冻结。

### 1. 解锁会话与秘密缓存（已确认）

- DEK 会话使用独立的 `unlock_idle_ttl`：省略时默认 `5m`，允许范围为大于零且
  不超过 `30m`；显式 `0s`、负值和超上限值均报配置错误。首版不支持永久解锁或
  每次访问重新解锁模式，不增加绝对会话寿命限制。默认值和上限是产品策略，非密码学要求。
- 条目秘密缓存使用 `cache_ttl`，默认 `0s` 表示禁用；保留 DEK 不等于缓存条目明文。
  启用缓存时不得超过解锁会话的有效期，锁定必须统一清除缓存，缓存命中不能绕过会话检查。
- 成功解锁后开始计算 idle 时间；成功执行需要解锁的凭据操作（含成功的秘密缓存命中）
  刷新 idle 时间。节点列表、配置元数据、doctor 检查、失败请求和等待锁不续期。
  持续成功访问可以保持解锁，idle TTL 不限制总解锁时长。
- 显式锁定或 idle 到期开始后，不再向新请求发放解密权限；尚未交付的请求在交付秘密前
  必须与锁定边界协调检查会话状态，若已经锁定则清理结果并返回 locked。取消并回收
  在途操作持有的材料后，才能报告锁定完成；不能仅清空会话中的 DEK 字段。
- 关闭或进程正常退出时不等待 TTL，尽力清零持有的 DEK 和秘密。Go 中无法保证擦除
  所有历史副本；已经交给调用方的秘密不撤回，已经建立的 SSH 连接不主动断开。
- 独立密钥文件模式同样执行 idle TTL；后续访问重新读取、校验密钥文件并自动解锁。
  只要文件仍可访问，锁定就不是禁止后续访问的授权开关，也不保证立即发现文件变更。

优势是减少重复输入与明文驻留，并使锁定边界可验证。代价是间歇操作可能重新提示，
禁用秘密缓存增加文件读取和 AEAD 解密，且需要会话版本检查及在途操作回收机制。
验收覆盖配置默认值与边界、续期条件、缓存命中与锁定竞争、在途结果拒绝交付、
关闭清理及密钥文件模式到期后重新校验；取消和回收的具体预算在决策 6 中确定。

### 2. 数据密钥代次与发布修订号（已确认）

- 使用两个独立标识：`dek_generation` 在生成新 DEK、全库重加密时变化；
  `vault_revision` 在改口令、更换包裹密钥、调整 KDF、升级或重加密发布时变化。
  首版不再增加独立的包裹修订号，普通 Put/Delete 不改变这两个标识，其事务见决策 4。
- 发布修订号在库级发布锁下递增，绑定认证元数据，发布标记必须与目标元数据的
  修订号一致。条目绑定 DEK 代次，不绑定每次变化的发布修订号，使改口令只需
  重新包裹 DEK。具体编码与发布标记校验协议在格式规范中固定，不能只用未认证计数器。
- 每次凭据操作（含秘密缓存命中）检查当前发布修订；发生变化时清除旧会话与缓存，
  按新元数据重新解锁。允许交互的入口可以提示，非交互主口令模式返回 locked，
  密钥文件模式重新读取并校验文件。仅调整 KDF 参数也使既有会话失效。
- 结果交付与发布切换必须有明确顺序；请求交付前发现修订变化，丢弃结果并返回
  可识别的状态变化错误，首版不无限自动重试。具体锁协议在决策 4 中确定，不能
  在检查修订后留下未经协调的结果交付窗口。
- 首版不增加跨进程主动通知或后台文件监听。空闲进程在下一次凭据操作时发现变化，
  或由 idle TTL 清理旧材料；不承诺修改发布后其他空闲进程立即清除 DEK。
- 这些标识只协调正常进程，不构成抗备份回滚的外部可信状态。改口令不能撤销其他
  进程已取得的 DEK；疑似泄露时仍需更换 DEK，并评估轮换实际服务器凭据。

优势是重包裹无需重写条目、跨进程失效行为明确且不依赖文件监听。代价是缓存命中
也需读取发布状态，元数据升级会触发重新解锁，遇到发布切换的在途操作可能需要重试。
验收覆盖同 DEK 重包裹后的会话失效、缓存命中检查、发布与结果交付竞争、非交互
失败关闭及空闲进程到期清理；不得以修订号递增测试代替完整备份回滚的边界说明。

### 3. 备份恢复、克隆与 nonce 预算（已确认）

- 创建备份原样保存密文，不重新加密、不消耗新 nonce；备份一致性由决策 5 的协议保证。
  显式恢复后可按套件安全策略验证和只读访问，普通写入必须等待新 DEK 全库重加密、
  读回验证及耐久发布完成，不能继承旧备份回退后的计数继续使用原 DEK 加密。
- 恢复原库时停止原库并发写入，保持 vault ID、StoreID 和 ItemID，更新 DEK 代次
  和发布修订号。克隆为独立库时生成新 DEK 和新 vault ID，保留 ItemID，显式确定
  StoreID 映射并按目标身份重加密；不支持复制目录后直接作为两个可写库使用。
- 正常加密采用先预留、后加密：在跨进程锁保护下先持久化消耗加密所需的预算，
  再使用 DEK 和新随机 nonce 加密。崩溃后无法确认是否使用的额度视为已消耗，
  失败操作和条目删除均不退还额度。首版逐次预留，不做批量额度预留优化。
- 完全相同的既有密文可以重试发布而不新增计数；任何重新加密必须消耗新额度并生成
  新 nonce。此规则同样适用于重加密目标库，不能只计最终成功提交的条目数。
- 新目标完成读回验证和耐久发布前，保留只读源副本，不开放普通写入、不删除源备份。
  恢复中断后可继续使用已持久化的新 DEK 和可靠的预算状态；无法证明预算可靠时，
  放弃该未发布目标，另建新 DEK 重做，不以猜测计数的方式续写。
- 随机 nonce 与次数预算只能约束碰撞概率，不能证明永不碰撞；格式规范必须根据
  nonce 长度及可接受风险确定上限。单库计数无法约束任意离线副本或恶意回滚，
  首版只支持显式恢复／克隆流程，不宣称能检测直接复制目录或回滚整个磁盘。
- 新 DEK 隔离后续加密，但不使旧备份或已泄露的服务器密码失效；实际凭据撤销仍需轮换。

优势是恢复后的写入与旧副本分离，预算不会因正常进程崩溃被低估。代价是每次加密
增加预算持久化，失败可能消耗额度，恢复／克隆需要全库重加密及额外磁盘空间。
验收覆盖预算持久化前后与加密前后的进程退出、同密文重试不重复计数、删除不退额、
恢复／克隆写入门槛、目标预算不确定时换 DEK 重做，以及原库引用保持和克隆身份绑定。

### 4. 普通读写与跨进程锁协议（已确认）

- 首版使用库级读写锁。`vault.lock` 位于库根目录，跨代次保留，不随发布替换或
  清理；移动或恢复库目录必须停止相关进程。使用操作系统文件锁，并在进程内统一
  协调，进程退出由系统释放锁，不以 PID 或时间猜测锁是否过期。
- Get 持共享锁检查发布修订、读取并认证条目、完成结果交付判定；秘密缓存命中
  同样遵守修订检查和交付边界。初始化、Put、Delete、重包裹、升级与物理 GC
  持独占锁。获取锁必须支持取消与有限等待，锁超时返回稳定错误。
- 解锁分两步：短暂持共享锁读取解锁元数据，释放文件锁后进行口令输入与 KDF；
  取得操作锁后重新检查修订，变化则放弃旧结果并返回状态变化错误。初始化也须
  在锁内重新确认库不存在，不能覆盖并发初始化的结果。
- 不持文件锁等待用户输入，不持配置 Repository、Registry 或会话状态互斥锁
  执行文件 I/O；会话互斥锁只保护短暂状态检查，不在其中等待文件锁。交付判定
  必须与决策 1 的锁定边界协调，不能把取得共享文件锁等同于会话仍然有效。
- Put 在独占锁内检查目标：已有条目先认证再比较秘密，同值幂等成功、异值冲突、
  损坏报错。目标不存在时先持久化预算预留，再加密、写临时文件并 sync，使用
  不覆盖目标的发布机制，最后同步目录。意外发现目标存在时返回冲突或重新验证，
  不无条件覆盖；各平台必须验证不覆盖发布的语义。
- 普通发布或删除已 Applied 但未确认 Durable 时，返回类型化的耐久性不确定错误。
  Put 未确认 Durable 时不得继续提交新配置引用，保留恢复 journal；Delete 的
  配置引用已解除，返回清理未完成并保留 journal。重试即使发现同值或目标已不存在，
  也必须完成必要同步，不能仅凭当前可见状态报告成功。
- 首版升级取得解锁材料后，在构建目标前取得独占锁并重新验证源修订，全程隔离
  目标构建、预算预留、读回验证和发布，直到完成或失败；暂不设计允许并发读取
  的升级协议。等待升级的普通访问可能超时，但不能转而读取旧代次。
- 物理 GC 的库锁仅保护文件操作；全局无引用检查与配置引用解除的耐久性仍由
  现有事务服务保证，不能用库锁代替配置引用安全判断。

优势是读取可并发、修改串行且事务边界容易验证，不需要自建过期锁恢复机制。
代价是同库写入和升级会阻塞其他访问，慢读取延迟写入，且各平台锁与文件发布
需要原生验证。验收覆盖并发初始化、同值／异值 Put、进程退出释放锁、取消等待、
发布与交付竞争、sync 失败后重试、升级隔离及 GC 引用安全边界。

### 5. 备份与 GC 的一致性（已确认）

- 首版采用停写备份，不提供在线一致性快照或跨配置、跨库的全局备份锁。维护流程
  必须停止相关 CLI/TUI/MCP 写入任务、定时任务、GC 和升级，覆盖配置、库及 journal；
  同一库被多个配置共享时，全部纳入停写范围。仅持有 vault.lock 不足以保证一致性。
  工具不能证明没有手工文件修改，停写是明确的运维前提，不能把运行中递归复制
  宣称为一致备份；停写持续到复制与完整性验证结束。
- 保存相关配置、journal、发布元数据、预算状态，以及恢复所需的全部代次和条目。
  不在备份过程中执行 GC、删除旧代次或筛除看似未引用的文件。主口令不进入备份，
  独立密钥文件单独备份保管，恢复时分别取得材料。
- 正常备份前先完成或恢复未决事务；无法解决时允许保存完整现场，但必须标记为
  需要事务恢复，不能报告为已验证可用的备份，也不自动修改现场来消除该标记。
- 备份清单记录文件相对路径、长度、哈希、库身份、发布修订及备份状态，不记录秘密。
  复制完成并验证后才标记完整。哈希检测漏拷、截断和意外损坏，不提供攻击者可同时
  修改清单时的真实性保证；恢复仍需验证 AEAD，配置与 journal 必须来自受信任来源。
- 恢复先进入独立受限目录，不直接覆盖当前库。先检查格式、权限、套件策略、文件
  完整性和事务状态，再取得解锁材料认证条目并核对配置引用；缺失引用、认证失败
  或未解决事务不得静默跳过。
- 确认可恢复后按决策 3 生成新 DEK、全库重加密并耐久发布，再开放普通写入。
  恢复完成、引用验证和耐久发布之前不运行 GC；之后再显式执行清理，保留源备份
  遵守既有显式清理规则。
- 备份指南必须给出可演练的停写、复制、验证、恢复及失败处理步骤，列出私钥文件、
  其他 Store 凭据等外部依赖。未包含这些材料时，不把离线库备份称为完整 SSH 环境恢复包。

优势是避免跨文件事务形成混合备份，保留恢复依据，失败时保留当前可用库。
代价是维护窗口、额外扫描与磁盘空间，以及旧代次和未引用条目造成的备份冗余。
验收覆盖共享库停写范围、未决事务标记、漏拷与截断、备份期间禁止清理、独立目录
恢复、引用完整性及恢复后写入和 GC 门槛；清单校验成功不等于来源可信或凭据可解密。

### 6. 超时预算、共享取消与 KDF 资源限额（已确认）

- 分开计时：`prompt_timeout` 默认 `2m`，包含 Prompt Gate 排队与一次人工输入；
  `unlock_timeout` 默认 `30s`，包含 KDF 排队、子进程启动、派生与结果校验，不含
  人工输入；`timeout` 默认 `10s`，覆盖解锁后的普通 Store 操作，包括文件锁等待
  与 I/O。显式重加密、恢复等维护操作使用独立总超时，默认 `30m`，不套用普通
  操作的十秒总预算。超时配置不允许以零或负值表示无限等待。
- 上述数值是初始产品策略，须经低配服务器实测确认。冷访问可以依次消耗多个阶段
  预算；调用方总 deadline 始终限制该调用方的等待，维护总预算也不能被阶段预算
  延长。不得因某个等待者的 deadline 到期而取消其他有效等待者共享的任务。
- 共享解锁由进程级会话管理器持有独立 context，每个等待者独立取消。单个等待者
  取消只移除自身，首个请求取消但仍有等待者时继续执行；全部等待者取消、显式
  锁定或进程关闭时取消任务，回收子进程、管道与材料。新请求不延长既有任务的
  deadline，旧任务完成回收后才能创建新任务。
- 非交互请求不得发起或加入需要人工输入的解锁任务，返回 locked；可以使用已经
  解锁的会话，或参与密钥文件模式自动解锁。首版 KDF 固定在受控子进程执行，
  超时或取消后终止并等待回收，禁止用遗留 goroutine 模拟及时返回。
- 每个 XOps 进程最多同时运行一个 KDF，最多排队八个不同库的解锁任务；同库等待者
  合并，不重复占用 KDF 队列。队列满立即返回可识别的资源繁忙错误，KDF 排队计入
  unlock_timeout。子进程回收完成前不释放运行名额。
- KDF 工作内存受程序策略约束，首版仅接受已确认的固定参数组合；完整 helper
  128 MiB 硬限额已通过原生验收，Argon2 内存参数不等于整个子进程 RSS。
  多个 XOps 进程的总资源限制由 cgroup、容器或平台部署机制承担，首版不增加
  跨进程 KDF 调度服务。
- 文件锁等待必须可取消；本地文件读写、fsync 等系统调用不保证被 context 立即
  打断。超时后停止启动后续普通步骤，在可取消边界退出并进行必要收尾；已经修改
  的状态按 Applied/Durable 返回，不统一声称未写入。不能遗留后台 goroutine
  伪造超时完成，锁定或关闭尚未回收完成时不得报告清理完成。
- 异常存储设备可能使实际返回时间超过预算。首版不扩展为全部文件 I/O 的进程隔离，
  也不承诺操作系统不可中断 I/O 的绝对退出时限。

优势是人工输入、正常 I/O 和维护操作互不误用预算，共享取消不受首个请求绑架，
低配服务器的 KDF 并发有界。代价是配置与任务状态机更复杂，不同库解锁串行且
繁忙时可能失败，受控子进程需要跨平台验证。验收覆盖阶段及调用方 deadline、
首个／部分／全部等待者取消、非交互加入拒绝、队列满与超时、内存参数拒绝、
子进程及管道回收，以及文件操作超时后的真实提交状态。

### 7. 解锁材料格式与错误分类（已确认）

- 主口令使用原始 UTF-8 字节。新建或改口令至少十二个 Unicode 字符，所有入口
  最多接受 1024 字节；拒绝无效 UTF-8、NUL、CR 和 LF，保留前后空格，不自动
  trim 或做 Unicode 归一化。终端回车提交是输入协议，不属于口令；Store 接收
  已去除输入分隔符的明确字节，各入口必须遵循同一规则。
- 解锁已有库不因未来提高创建门槛而拒绝旧口令，仍执行格式及资源上限检查。
  初始化、改口令输入两次确认；Store 内不自动循环重试解锁。十二字符只是最低
  门槛，不保证强度；外观相同但编码不同的口令可能不相等，空格必须准确保留。
- 密钥文件只接受恰好 32 字节的普通文件，不自动识别 hex、Base64 或忽略尾随
  换行，任何字节都属于密钥。文档要求密码学安全随机源生成；长度检查不能证明
  随机性，任意 32 字节文本不能据此称为安全密钥。
- POSIX 允许当前有效用户或 root 持有密钥文件，禁止组和其他用户访问，禁止
  可执行位，兼容 0400、0600 的常见部署。Windows 验证所有者和有效 ACL，
  只允许当前用户及受信任系统管理主体访问，具体主体规则须经平台规格与验收固定。
  安全打开并校验实际文件，拒绝符号链接和不安全路径替换，不自动修改权限。
- 首版支持显式主口令／密钥文件模式转换，作为重包裹事务：验证旧材料，获取并
  验证新材料，重新包裹同一 DEK，读回验证后原子发布新修订，并按决策 2 失效
  旧会话。沿用可恢复发布协议，不自动生成或删除用户供应的密钥文件；疑似泄露
  仍走更换 DEK 的完整流程，旧备份仍可用旧材料解锁。

错误按可确定原因分类，下表为语义名称，实施时映射到现有错误体系：

| 情况 | 返回语义 |
| --- | --- |
| 未解锁、非交互缺少主口令、DEK 包裹认证失败 | locked |
| 条目认证失败、明确的结构损坏或截断 | corrupt |
| 未知版本、未知套件、退役策略禁止使用 | unsupported／策略拒绝 |
| 库或密钥文件不存在 | unavailable |
| 文件权限不安全、访问被拒绝 | 权限拒绝 |
| 库有效且已解锁，请求条目不存在 | not-found |
| 同 ItemID 已存在不同秘密 | 冲突 |
| 发布修订在操作期间变化 | 状态变化 |
| KDF 队列已满 | 资源繁忙 |
| 取消、超时、耐久性不确定 | 保留各自类型及原始原因 |

错误顺序遵循安全访问、受限解析、认证、条目查找，不为细分原因绕过前置检查。
错误口令与被篡改的 DEK 包裹密文都可能认证失败，统一返回 locked；提示应为
“无法解锁，请检查解锁材料或库完整性”，不能断言“密码错误”。错误与日志不包含材料内容。

优势是输入解释唯一、调用方可按稳定原因处理失败，模式转换无需重写条目。
代价是文本部署密钥需要预先转换，组共享权限不受支持，Unicode 和空格必须准确，
且包裹认证失败不能精确诊断。验收覆盖多入口字节一致性、长度与编码边界、确认输入、
原始密钥长度、权限和路径竞争、模式转换中断恢复、旧会话失效及错误分类与脱敏。

### KDF 参数与内存策略（规格决策已确认）

- 首版 Argon2id 固定为内存 65536 KiB、迭代次数 3、并行度 1、派生输出 32 字节。
  普通读取与写入均只接受这一组合，不提供任意参数范围或低成本回退。以后通过
  审核过的参数档位扩展读写策略，已有库使用显式重包裹升级，不能静默转换。
- 64 MiB 是 Argon2 工作内存，不包括 runtime、栈、管道和协议开销。完整 helper
  以 128 MiB 为候选总内存预算，必须通过实现后的测量与验收才能定为产品限额；
  宿主 CLI/TUI/MCP 及秘密缓存内存单独计算，helper 限额不约束宿主进程。
- 保持单进程一个 KDF 的限制。GOMEMLIMIT 仅是 Go 软目标，不是硬限制；能够
  可靠限制子进程内存的平台应设置硬限制，不能提供同等机制的平台须明确保证边界，
  不先承诺跨平台统一硬上限。达到限额时回收 helper 并返回资源错误，不降低参数。
- 执行前利用可获得的主机与容器内存信息做资源预检，已知余量不足则提前拒绝。
  首版不凭一次测量冻结通用可用内存门槛；预检结果会变化，也不能避免多个 XOps
  进程同时启动。预检只减少失败，不替代进程限制与部署资源配额。
- 完整 helper 的新进程首次解锁、重复解锁须在隔离环境测量耗时分布和峰值内存，
  保留最慢样本，验证 128 MiB 候选限制下稳定完成且有合理余量。资源不足、触及
  内存限制、取消、超时、多库排队和非法头部测试不得在运行中的 受限资源测试环境 上进行压力实验。
- 验收必须确认非法参数在执行 KDF 或大额分配前拒绝，队列不放大工作内存，失败
  关闭且没有残留子进程、管道或秘密输出。若完整 helper 超过候选预算，先分析
  开销再优化或调整进程预算，不自动降低 Argon2 参数。
- 受限资源环境限流初测只支持低配可行性，不证明密码学强度或完整解锁超时。冻结依据包含
  配套工程安全评估、独立向量及原生 128 MiB 限额/解锁超时测试，见冻结记录。

优势是参数和解析白名单简单、资源行为易验证，避免用户无意降低 KDF 成本。
代价是首版不能利用高配置机器自由增加成本，并且平台内存限制与完整 helper 开销
需要分别验证。后续高成本档位可独立评估，无需为首版接受尚未测试的参数组合。

### 密码学格式 v1（规格决策已确认）

- 使用固定布局的二进制封套，字段顺序固定，整数统一大端序；元数据与条目使用
  不同的固定 magic，后接容器版本。可变字段带长度前缀，先校验长度再读取或
  分配。v1 不提供任意扩展或可选字段，未知版本、额外尾随字节直接拒绝；新增
  字段通过新容器版本引入。诊断由 CLI 输出经过筛选的元数据，不直接展示文件载荷。
- 不直接使用 YAML 或普通 JSON 序列化结果作为 AAD，避免字段顺序、重复字段和
  数字编码的规范化歧义。AAD 使用格式规定的原始规范头部字节。
- 首版分别分配三个固定套件 ID，编号一经分配不得复用：主口令包裹使用已确认
  参数的 Argon2id、32 字节派生密钥和 AES-256-GCM；密钥文件包裹使用原始
  32 字节密钥、HKDF-SHA-256、32 字节派生密钥和 AES-256-GCM；条目使用
  所属 DEK 代次的 AES-256-GCM。未来算法或参数调整使用审核过的新套件或档位，
  不允许自由组合算法。

| 字段 | v1 约束 |
| --- | --- |
| vault ID | 16 字节安全随机值 |
| Argon2id salt | 16 字节安全随机值，每次重包裹重新生成 |
| HKDF salt | 32 字节安全随机值，每次重包裹重新生成 |
| GCM nonce | 12 字节 |
| GCM tag | 16 字节，禁止截短 |
| DEK | 32 字节 |
| DEK 代次、发布修订号 | 无符号 64 位整数，从 1 开始，溢出拒绝操作 |

- HKDF info 使用版本化用途标签，并绑定 vault ID 与 StoreID；语义为
  `XOps / encrypted-file / v1 / key-file-wrap / vault ID / StoreID`。
  此处仅示意字段含义，实际使用长度明确的二进制编码，不以斜杠拼接字符串。
  StoreID 变更需要显式转换，不能只改配置中的名字。
- 封套为“规范头部 + 密文及认证标签”。包裹 DEK 的 AAD 包括文件类型、容器版本、
  包裹套件、KDF 参数及 salt、vault ID、StoreID、DEK 代次、发布修订号和 nonce。
  条目 AAD 包括文件类型、容器版本、条目套件、vault ID、StoreID、ItemID、DEK
  代次和 nonce，不绑定发布修订号，保持改口令无需重写条目的约束。
- 读取时将头部身份与请求的 StoreID／ItemID 和当前库身份比较；仅认证文件自带
  头部不能证明文件对应请求。既有头部认证与套件校验要求继续适用，不能因本节
  字段摘要遗漏某个相关标识而将其排除在认证之外。
- 单条秘密明文最多 64 KiB，空秘密拒绝；单个元数据文件最多 4 KiB。StoreID、
  ItemID 的编码上限须核对现有引用校验契约后固定，不引入未经核对的不兼容限制。
  条目文件大小上限由头部上限、64 KiB 明文及固定 tag 长度计算，禁止额外数据。
  私钥文件本身不进入 Store；未来扩展为大秘密存储需要另行设计。

优势是字节解释唯一、资源边界可验证、密钥用途与身份绑定清楚，重包裹无需重写
条目。代价是不能手工编辑二进制文件，身份变更须执行转换，格式扩展需要版本升级。
验收须包含独立编码测试向量、长度与整数边界、未知版本、尾随数据、跨身份替换、
套件错配及仅重包裹不改条目的验证。具体 magic、套件编号、字段偏移、长度前缀宽度
和 HKDF info 精确字节仍须在格式表中落实；nonce 次数上限遵循下述使用预算决策。

### 加密次数上限与 nonce 预算（规格决策已确认）

- 首版每个 DEK 最多执行 `2^20`（1,048,576）次条目加密，nonce 为独立均匀生成的
  96 位随机值。计数是实际加密次数而非当前条目数；沿用先持久化预留、后加密的
  协议，失败和删除不退还额度，崩溃后不能确定是否使用的额度视为已消耗。
- 在上述随机假设下，q 次加密发生至少一次 nonce 碰撞的概率近似为
  `q * (q - 1) / 2^97`；q 为 `2^20` 时约为 `2^-57`，即 `6.9 × 10^-18`。
  这只描述 nonce 碰撞风险，不是 AES-GCM 整体安全界限；格式冻结前须结合
  64 KiB 条目上限、AAD 长度及认证尝试量完成安全审查，不能宣称随机 nonce 永不碰撞。

| 操作 | DEK 条目加密预算 |
| --- | --- |
| 新条目加密、失败后重新加密 | 消耗新额度 |
| 完全相同的既有密文重新发布 | 不新增计数 |
| 已有 ItemID 同值检查、Get、认证、删除 | 不消耗额度 |
| 全库重加密 | 消耗新 DEK 的额度 |
| 改口令或仅重新包裹 DEK | 不消耗条目预算，遵循包裹密钥单次使用规则 |

- 全库重加密预检必须确认目标条目集合可容纳于新 DEK 的上限内，目标库同样
  持久化预留预算；中途耗尽不得发布不完整目标。
- 从 DEK 通过 HKDF-SHA-256 派生专用预算认证密钥，用 HMAC-SHA-256 认证预算
  记录，绑定 vault ID、StoreID、DEK 代次与已消耗次数。派生用途与其他用途严格
  域分离，具体字节编码及测试向量在格式表落实。预算不含秘密，无需 GCM 加密，
  避免为了记录一次加密递归消耗 nonce。
- MAC 检测直接修改，不检测完整旧记录回滚；继续遵守显式备份恢复与克隆边界。
  预算损坏或不能确定是否耐久时，禁止新条目加密并进入恢复流程，不猜测计数。
- 已消耗额度达到 90% 时，通过状态信息由 CLI/TUI 提示显式重加密，pkg 不主动
  打印。达到上限后返回可识别的密钥使用量耗尽错误，拒绝新条目加密；继续允许
  符合安全策略的读取，以及预算状态可靠时的清理。普通 Put/Get 不自动触发全库升级。
- 每次新包裹生成新 salt 和新 nonce，派生出的包裹密钥只执行一次 DEK 加密。
  重试只能复用完全相同的包裹密文，重新加密须重新生成 salt 和 nonce；包裹路径
  不维护长期加密计数。salt 碰撞与派生密钥重复概率仍须纳入整体安全审查。

优势是低频凭据写入有明确余量，预算认证不递归消耗 nonce，到限行为可预期。
代价是需要预算认证格式、恢复与显式轮换，未及时处理预警会阻止新秘密保存。
验收覆盖上限前后、90% 提示、失败不退额、既有密文重试、MAC 篡改、预算耐久性
不确定、目标重加密容量预检及包裹重试规则；不能以单次往返或碰撞压力测试替代安全分析。

### 文件布局、原子发布与恢复状态机（规格决策已确认）

- 库根目录与 vault.lock 保持稳定，CURRENT 为唯一发布入口，指向 revisions 下的
  当前完整发布目录并绑定对应元数据摘要。key-state 按 DEK 代次保存认证预算，
  transactions 按操作 ID 保存无秘密的恢复状态。改口令后 DEK 不变时，新旧修订
  共享同一预算，不能复制成两个可独立消耗的计数器。
- 首版改口令和调整包裹方式也建立完整目标目录：复制既有条目的密文字节，只重新
  包裹 DEK，不消耗新的条目加密预算。全库重加密则生成新 DEK 和新条目密文。
  首版不用硬链接；“只重新包裹”表示无需条目重加密，不表示无需复制文件或额外空间。
- 发布顺序为目标文件写完并 sync、读回认证与集合校验、同步目标目录和必要父目录、
  写出并同步临时 CURRENT、原子替换 CURRENT 并同步库根目录、重新打开验证。
  该过程遵守库级独占锁要求，不依赖替换非空目录。
- 读取只跟随 CURRENT，不扫描并选择编号最大的目录。指针必须与目标元数据的
  修订号、摘要和认证结果一致，不能单独信任指针字段。各平台文件替换与目录耐久性
  机制分别实现、原生验证；未经验证的平台不能宣称具有相同保证。

| 阶段 | 含义 | 中断后的处理 |
| --- | --- | --- |
| prepared | 已记录源修订、目标修订和操作意图 | 源未变时可以继续 |
| building | 正在构建目标 | 按预算规则继续；预算不可靠时换新 DEK 重建 |
| verified | 目标完整，已验证并同步 | 重新验证源与目标后允许发布 |
| published | CURRENT 已切换 | 核对实际指针，不重复切换 |
| committed | 发布已确认耐久，重新打开验证成功 | 正常使用，旧副本等待显式清理 |
| cleanup_pending | 用户已请求清理，尚未完成 | 幂等继续清理，不影响当前发布 |

- 日志阶段只是恢复线索，必须与实际 CURRENT、元数据和预算交叉核对。源修订
  已变化时停止旧任务，不覆盖新发布；发布已发生但耐久性未确认时保留新旧目录，
  返回不确定状态，恢复时核实当前状态并完成必要同步，不盲目回滚或重复切换。
- 显式清理持库级独占锁，确认目标不是当前发布、没有未完成事务依赖目标。删除
  对应预算前，确认没有当前发布或待恢复事务使用该 DEK 代次；清理同 DEK 的旧
  修订不能删除当前修订仍使用的预算。删除后同步必要目录，失败保留 cleanup_pending，
  不回滚成功的新发布；预算回滚与旧备份边界继续遵守既有决策。
- 普通 Put/Delete 不切换 CURRENT：Put 为持久化预算预留、临时密文写入并 sync、
  不覆盖发布、目录 sync；Delete 在配置引用解除且耐久后删除并同步目录。
  CredentialService journal 继续负责配置与 Store 的跨层事务。

优势是发布入口唯一、目标目录完整、密钥预算生命周期独立，恢复不依赖拼接目录。
代价是重包裹仍需复制密文和额外磁盘空间，清理须理解发布与 DEK 两种生命周期，
且需要逐阶段故障注入。验收覆盖 CURRENT 与阶段日志不一致、源修订变化、发布
耐久性不确定、重包裹共享预算、预算损坏重建、清理引用检查及普通条目事务。
平台系统调用、指针精确编码和各阶段故障恢复表仍须在实施规格中落实。

### KDF 内部协议与子进程回收（规格决策已确认）

- 同一 XOps 二进制提供私有 KDF 入口，每个子进程只处理一个请求、返回一个
  结果并退出；不复用通用 credential helper 协议，不建立常驻服务。直接执行
  当前二进制，不经过 shell。入口在普通 CLI 配置初始化之前分流，不加载配置、
  访问凭据库、接受文件路径或启动 TUI、MCP、日志初始化及迁移。
- 子进程仅执行 Argon2id 并返回 32 字节派生密钥；父进程负责安全读取、参数校验
  及 DEK 解包认证。每次冷解锁承担进程启动成本，以取得工作内存释放与取消边界。
- 使用版本化二进制单请求／单响应协议，首版父子版本严格匹配，不回退旧协议。
  请求包含 magic、协议版本、请求长度、操作类型、Argon2id 参数、salt、口令
  长度及口令字节；响应包含 magic、协议版本、响应长度、状态码，成功载荷恰好
  32 字节，失败仅固定错误码，不携带自由文本。
- 请求总长度最多 2 KiB，响应总长度最多 256 字节，口令仍受 1024 字节上限约束。
  父子进程均检查固定 KDF 参数、版本与长度；拒绝截断、多帧、尾随字节、未知
  状态和不匹配长度，非法请求在 KDF 或大额分配前拒绝。
- 秘密仅通过匿名管道传输：父进程写完 stdin 请求后关闭写端，子进程有界读取
  并确认 EOF 后执行 KDF；stdout 仅输出协议响应。主口令和派生密钥不进入 argv、
  环境变量、临时文件、日志或 journal；子进程使用最小必要环境，不继承无关业务变量。
- 父进程并行处理有界 stdout 和 stderr，避免管道互相等待。stderr 持续排空，
  最多保留 4 KiB，不向用户原样输出；超过上限视为协议异常并终止进程。所有
  I/O 任务必须可等待回收，暂存材料尽力清零。
- 父进程仅在收到恰好一个合法成功响应、stdout 正常结束且无额外数据、子进程
  以零状态退出、调用未取消或超时且共享任务仍有效时接受密钥。先收到结果后
  异常退出也须丢弃并清零；KDF 成功不代表口令正确，父进程 DEK 的 AEAD 认证
  失败按既有规则返回 locked。
- KDF 无文件提交事务，取消时直接终止受控进程组或 Job，不等待长时间优雅退出。
  Linux/macOS 使用独立进程组并终止整组；Windows 在执行工作前加入具有关闭
  即终止语义的 Job。关闭管道，等待 I/O 任务和进程回收后才释放 KDF 运行名额，
  回收前不报告锁定或关闭完成。
- 父进程崩溃后的回收逐平台明确：Linux 可结合父进程死亡信号，Windows 依赖
  Job 生命周期；macOS 必须验证父进程存活监测与管道关闭机制，不能假设父进程
  退出自动终止子进程。回收仍受操作系统调度影响，不承诺不可中断内核状态下的
  绝对退出时限。
- 资源限制触发、协议错误、异常退出返回可识别原因；取消与超时保留原始语义，
  不回显子进程载荷。保持单 KDF、八个不同库排队和已验收的 128 MiB 限额。排队、
  启动、派生、结果校验及正常回收计入 unlock_timeout，超时后的必要回收不能省略。

优势是子进程职责与输入面小、结果和退出状态一致、取消能停止计算；代价是进程
启动和跨平台回收成本，以及管道、环境和缓冲区生命周期管理。验收覆盖请求／响应
边界、EOF、多帧、超量 stderr、成功响应后异常退出、超时与结果竞争、父进程
退出、进程组／Job 回收及秘密不进入诊断输出。magic、错误码编号和精确字段布局
仍须在内部协议表中落实，父进程崩溃回收须有各平台原生证据。

### CLI 接口与平台支持边界（规格决策已确认）

离线库管理归入现有 credential store 命令树，以下命令已在阶段 E 接入：

| 命令 | 职责 |
| --- | --- |
| `credential store init <storeID>` | 初始化已配置的离线库，不覆盖既有库 |
| `credential store inspect <storeID>` | 查看版本、套件、修订和容量状态，区分认证状态 |
| `credential store rewrap <storeID>` | 改口令、更换密钥文件或转换解锁模式，不换 DEK |
| `credential store reencrypt <storeID>` | 新建 DEK，全库重加密 |
| `credential store resume <storeID>` | 恢复中断的维护事务 |
| `credential store restore <storeID> --from <backup>` | 备份恢复，经验证和换 DEK 后开放写入 |
| `credential store clone <sourceID> --to <targetID>` | 创建独立库身份和 DEK |
| `credential store prune <storeID>` | 显式清理不再需要的旧发布目录及预算 |

- gc 继续处理引用解除后的条目清理，prune 处理库内部旧发布，finalize-migration
  只处理旧 v1 材料。init 要求 Store 已显式配置，不顺便修改 default_store；
  涉及配置转换的操作必须显式指定，不隐式改写所有调用方配置。
- 首版不提供独立 CLI unlock／lock 或跨进程会话控制，不增加 IPC 或常驻代理。
  CLI 按需解锁，TUI 提供当前进程会话的锁定／解锁；MCP 主口令模式不增加远程
  传入口令的接口，未解锁时失败关闭，无人值守使用密钥文件模式。不同 CLI 进程
  可以分别提示，外部命令不能立即锁定正在运行的 TUI。
- inspect 默认不解锁，只读取有界元数据，文件内版本、身份和修订标记为尚未认证。
  认证或读取预算等完整状态通过显式 --verify 执行；doctor 保持非交互，不因
  诊断自动提示主口令。未经验证的文件头不能当作可信容量或身份状态。
- 维护命令不接受口令或密钥内容作为 argv、环境变量；主口令仅隐藏输入，密钥
  文件仅传路径。非交互缺少材料直接失败。prune 默认展示清理计划，实际删除
  要求显式 --apply，并继续执行清理安全检查。
- resume 根据 journal 和实际状态恢复，不让用户手工指定当前阶段。恢复、克隆
  或升级遇到既有目标失败关闭，不提供通用 --force 覆盖开关；对既有事务的恢复
  由 resume 按状态机处理。维护操作使用独立总超时，CLI 统一呈现类型化错误。
- 备份首版提供停写操作指南，不新增可能被误认为在线一致性备份的命令。
- 首个正式支持平台为 Linux amd64，ext4、XFS、Btrfs 为本地文件系统验收矩阵。
  文件系统类型不是访问白名单，其他类型由部署者保证可靠性；必要文件操作失败时
  返回明确错误，不静默省略同步或权限检查。Windows、macOS 和其他架构在原生
  实现与验收后加入平台矩阵，当前仍返回不支持；不改变现有后端的平台支持。
- 受限资源测试环境 当前只提供 KDF 初测证据，未验证其文件系统或完整事务能力，不等于 Linux
  后端验收完成；交叉编译成功也不能替代原生验收。
- Windows ACL 信任主体方向为当前用户、SYSTEM 和本机 Administrators；拒绝
  其他主体读取／修改密钥，以及修改其所有权或 ACL 的权限。检查有效权限，不能
  仅检查某条 Allow ACE；域组与继承 ACL 等部署情况须额外评估。精确规则在
  Windows 支持前完成原生验证。

优势是命令职责明确、进程内会话语义真实、平台承诺可以逐项验证。代价是命令与
帮助信息增加，维护需分步操作，首版支持范围较小，企业 ACL 需额外评估。
验收覆盖命令职责与参数校验、初始化不改默认 Store、非交互失败、inspect 认证
标记、prune 计划与执行、恢复冲突、平台拒绝及 ACL 有效权限；完整选项表、错误
呈现和平台探测规则仍须在实施规格中落实。

后端集合已增加 encrypted-file，ADR-0001 后端表和使用说明已同步。
配置与秘密分离、显式选择、失败关闭及 none 默认策略保持一致；KDF 使用受控子进程。

## 实施与验收

1. 固定威胁模型、分层版本、套件表、参数与 nonce 使用上限，以及升级状态机和原子发布
   机制；使用标准库 AES-GCM 和现有 x/crypto 依赖，不增加运行时包依赖。
2. 实现文件 Store 和故障矩阵：错口令、篡改、超限、路径、权限、并发、幂等写入、sync 失败。
3. 实现解锁会话、受控 KDF、超时取消、清零、并发首次访问及 idle lock。
4. 接入 Schema/Registry/CLI/TUI/MCP/doctor/GC/迁移；逐命令验证非交互边界。
5. 验证低内存 Linux、Windows、macOS 与只有单个二进制的隔离环境；补充备份恢复指南。
6. 实现显式重包裹/重加密、只读兼容、受限迁移和旧代次清理，验证升级不会隐式降级。
7. 执行完整 build/test/race/lint，并通过以下安全验收；不能仅验证加解密往返成功。

安全验收至少包含：

- 使用标准测试向量和独立实现核对 KDF、HKDF、AEAD 与认证数据编码；对密码学
  封套、密钥生命周期和升级协议进行独立代码审查，发现的问题关闭后再发布。
- 修改头部版本、套件 ID、KDF 参数、salt、nonce、tag 或密文，以及跨 ItemID、
  StoreID、vault ID、密钥代次交换记录，均不能被静默接受。
- 格式 fuzz 覆盖截断、重复/未知字段、整数溢出、超大长度、恶意 KDF 参数、未知
  套件及多义编码；拒绝输入时不触发超限内存分配、无限阻塞或秘密日志。
- 验证随机源失败、nonce 分配规则、密钥使用上限和多进程幂等重试；不得依赖
  “压力测试里没有观察到碰撞”来证明随机 nonce 永不重复。
- 覆盖所有受支持旧格式到新格式的升级、旧写入拒绝、退役策略执行以及未知版本
  失败关闭；恢复日志不能绕过退役策略。
- 在每个升级阶段注入失败与真实进程退出，包含源文件并发修改、磁盘满、目录
  sync 失败和部分新文件落盘；验证至少保留一个可恢复副本，读者不见混合代次。
- 验证 DEK/秘密缓存随锁定和代次变化失效，取消后无残留子进程、pipe 或 goroutine；
  日志、错误、argv、YAML、快照与 journal 不包含秘密或解锁材料。
- 验证旧备份恢复路径，并确认旧备份不具备可信新鲜度；演练密钥丢失、旧算法失守和
  已泄露凭据的轮换流程，不把恢复或重加密描述为撤销历史泄露。

每个阶段单独验收；在解锁机制、格式安全和恢复测试齐备前，不切换用户配置或迁移真实秘密。
