# ADR-0002：受限资源环境 KDF 测量

- 日期：2026-09-10
- 关联：[ADR-0002](0002-offline-encrypted-credential-store.md)
- 测量类型：小样本资源可行性测试

## 环境与参数

测试环境为 Ubuntu 24.04、Linux amd64、1 个逻辑 CPU、约 1 GiB RAM，无 swap。
探针使用 Go 1.26.7、golang.org/x/crypto v0.55.0、CGO_ENABLED=0 编译。

每个进程执行一次 Argon2id，工作内存为 65536 KiB，并行度为 1，输出为 32 字节。
输入为固定公开测试材料，派生密钥不写入输出。探针使用 17 字节 salt；
格式 v1 使用 16 字节 salt，该测量不作为格式兼容性验证。

测试 unit 的限制为：

```text
CPUQuota=10%
CPUQuotaPeriodSec=100ms
MemoryMax=128M
MemorySwapMax=0
Nice=19
RuntimeMaxSec=20s
LimitCPU=2
LimitCORE=0
TasksMax=16
GOMAXPROCS=1
GOMEMLIMIT=96MiB
```

已核对 cpu.max=10000 100000、memory.max=134217728。追加采样串行执行，
间隔两秒；采样前检查可用内存不低于 384 MiB、memory PSI some avg10 为零。
测试 unit 和探针进程完成后回收。

## 结论与范围

- 九次测试均在 128 MiB 硬限额内退出，峰值 RSS 为 66.25 MiB。
- t=3 最慢样本约 7.63 秒，与 30 秒单次解锁预算相容；队列等待和多库争用未包含在测量中。
- 每组包含三个样本，未进行显著性检验。
- 墙钟时间包含 CPU 配额等待，不能直接作为无配额环境的解锁延迟。
- 探针资源用量不能用于推断完整 helper 的 RSS 上限或密码学安全强度。

格式 v1 已固定 Argon2id 64 MiB、t=3、p=1、输出 32 字节。
完整 helper 的限额、取消和进程回收验证见[原生部署记录](../plans/offline-encrypted-credential-store-deployment.md)。
