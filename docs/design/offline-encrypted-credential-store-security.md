# 离线凭据库阶段 A 密码学安全评估

- 日期：2026-09-10
- 范围：当前 `internal/credentialfile/format` 与 `internal/kdfhelper` 的格式和协议基础
- 依据：[ADR-0002](../adr/0002-offline-encrypted-credential-store.md)、[格式规格](offline-encrypted-credential-store-format.md)
- 性质：工程安全界限分析与代码核对，不是第三方安全认证或对完整后端的审计

## 1. 结论与适用条件

当前格式可保留 AES-256-GCM、96 位随机 nonce、128 位完整 tag、每 DEK 最多
2^20 次加密、64 KiB 单条秘密和固定 Argon2id 参数。核对未发现需要更换算法、
降低加密预算或修改字节布局的问题。阶段 A 的安全评估记录与确定性边界测试缺口
已补齐；这不表示尚未实现的文件事务、随机材料生成、会话和子进程回收已经验收。

量化结论依赖以下条件：

- AES 的密钥恢复/区分攻击、HMAC/HKDF 的 PRF 攻击与 SHA-256 碰撞/第二原像
  攻击没有突破相应计算安全假设；下文数值不包括未知的原语破坏优势。
- DEK/密钥文件来自安全随机源；主口令猜测风险单独考虑，不能以密钥长度替代熵。
- 每个 DEK 的所有实际加密遵循耐久预留预算和新 nonce；库副本共享密钥的风险
  按显式恢复/克隆换 DEK 规则控制。直接回滚或复制可写目录不在保证内。
- 长度和套件检查先于密码学处理，读取不向调用方交付未认证明文。
- 攻击者不能直接读取进程密钥或以同用户/root 修改运行程序。此类攻击以及硬件
  故障、系统旁路、物理擦除、侧信道不由本格式提供防护证明。

## 3. 消息长度与密码学操作预算

最大条目头部（全部进入 AAD）为 `67+1024+1024=2115` 字节，密文正文最多
65536 字节，tag 不作为 GHASH 密文正文再次计算。因此：

```text
AAD blocks        = ceil(2115 / 16) = 133
ciphertext blocks = ceil(65536 / 16) = 4096
length block      = 1
L                 = 4230
q                 <= 1048576
q * L             <= 4435476480
```

RFC 9001 的 l 不包含最后的长度块，本评估统一使用更大的 L=4230，避免低估。
累计 GHASH 分组超过 2^32 不等于 GCM 被突破，也不是把 NIST 的调用次数限制
解释为总 GHASH 分组上限；它必须进入安全界限计算，而不能仅查看每条消息长度。
包裹 DEK 的最大 AAD 为 1132 字节，DEK 两个分组，加长度块得到 L_wrap<=74。

## 4. nonce 碰撞与保密性

独立均匀的 96 位 nonce，在最多 q 次加密中的碰撞事件用 union bound：

```text
R_nonce <= q(q-1) / 2^97
q=2^20 时 R_nonce <= 6.9388872865e-18，约 2^-57
```

在没有该事件的条件下，使用 RFC 9001 B.1.1 的保密性主项，并以 L 保守代入：

```text
R_conf,main <= 2(qL)^2 / 2^128
            = 1.1563015611e-19，约 2^-62.91
```

保密性评估把 nonce 事件与构造项相加，并保留 AES 的计算优势项；不能把两个
概率相乘，也不能将 AES-256 的密钥长度描述为 256 位 GCM 完整性强度。
有效 tag 只有 128 位，随机 nonce 的碰撞事件在上述工作量下是更大的贡献。

## 5. 认证失败尝试与保守完整性包络

定义 v 为同 DEK 下攻击者提交的新伪造验证尝试数。重读相同的合法文件不产生
新的加密预算；任意多伪造尝试不能被“q 已有限制”自动约束。

在理想独立掩码/均匀 GHASH 密钥模型中，首次成功伪造前，长度至多 L 的一次
尝试排除/命中的 GHASH 密钥候选最多按 L 估计。对 v 次自适应失败路径使用：

```text
R_poly <= min(1, vL / (2^128 - vL))，仅当 vL < 2^128
```

分母保留此前失败的条件化影响，不只写成无限适用的 `v/2^128`。为把理想模型
与实际 AES 分组置换连接，保守地把每次伪造也按完整 L 个分组工作计数：

```text
sigma <= (q+v)L + 1
R_switch <= min(1, 2 sigma^2 / 2^128)
R_engineering <= min(1, R_nonce + R_switch + R_poly)
                + 原语计算优势项
```

`+1` 计入生成 GHASH 密钥的块。R_switch 使用高于通常置换/随机函数切换项的
系数，重复/失败验证也全部计入，得到故意偏松的工程包络。它与上述保密性主项
有重叠，使用包络时不再额外叠加 R_conf,main。这是有假设的组合分析，不是对
所有实际攻击、所有工作量和所有实现的无条件安全证明。

| q | v | R_engineering（不含原语计算攻击） |
| --- | --- | --- |
| 2^20 | 1 | 约 7.055e-18 |
| 2^20 | 2^20 | 约 7.401e-18，约 2^-56.91 |
| 2^20 | 2^32 | 约 1.941e-12，约 2^-38.91；偏松切换项主导 |

最后一行表示此保守分析的保证变弱，不是观测到实际可行的伪造攻击。实现没有
跨备份不可回滚的 v 计数器，不能宣称对无限尝试仍有固定失败概率。后续运行层
应对认证失败立即失败关闭、给出完整性错误且不自动无限重试；如部署要求明确
的累计攻击预算，必须在其可控制的范围监测/约束，不能依靠可被复制的本地文件
声称限制离线攻击者。本次不新增未经讨论的自动锁死或永久禁止读取策略。

## 6. 多密钥、重包裹和口令猜测

对 K 个不同 DEK 的系统，使用 `sum(R_i)` 的 union bound，而非认为每库概率
就是整个系统概率。例如每库 q=v=2^20 时，K=10^6 的上述包络约 7.4e-12。
部署方需按实际密钥数量和访问量评估；不使用单用户结论声明任意规模安全。

每次包裹使用新 salt、新 nonce、单次派生密钥；完整同密文重试不再调用 Seal。
对共享同一解锁材料的 r 次重包裹，保守地将 salt 重复视为需重新分析的事件：

| 模式 | salt 位数 | r=2^20 的 salt 碰撞上界 |
| --- | --- | --- |
| 主口令 | 128 | 约 2^-89 |
| key-file | 256 | 约 2^-217 |

盐重复未必导致 nonce 重复，但不能继续声称派生密钥只使用一次；这里采用保守
事件计入，不乘以 nonce 碰撞概率来缩小风险。输出 256 位派生密钥的碰撞/伪随机
性仍依赖 KDF 假设，不能只计算 salt 就省略。单包裹密钥的 GCM 分组预算按 L_wrap
与其验证次数单独计算。

Argon2id 使用 v0x13、m=65536 KiB/t=3/p=1/output=32，已与 libargon2 独立
输出核对。此配置是项目低配策略，不宣称等于所有标准推荐的完整参数档位。
12 个 Unicode 字符不等于 12 字节或固定熵，不能量化为统一的离线破解年限；
用户口令分布决定猜测风险。vpsc 测量只是资源可行性，不能充当攻击成本下界。

## 7. HKDF、HMAC 与摘要绑定

| 用途 | IKM | salt | info 绑定 |
| --- | --- | --- | --- |
| key-file 包裹 | 独立随机 32 字节文件 | 新 32 字节随机 salt | 固定 wrap 标签、vault ID、StoreID |
| budget MAC | DEK | vault ID | 固定 budget 标签、StoreID、DEK 代次 |
| transaction MAC | 相应端 DEK | 该端 vault ID | 固定 transaction 标签、StoreID、DEK 代次 |

采用 HKDF Extract+Expand，输出 32 字节；LP 编码与固定宽度字段使 info 无拼接
歧义，info 不由秘密值本身构造。MAC 路径 IKM 已是随机 DEK，vault ID 作为公开
salt 不需要提供口令式猜测成本。AES 直接使用 DEK，MAC 使用域分离派生值，
其组合依赖 AES/HMAC/HKDF 的计算安全，不声称这些相关材料信息论独立。

预算和 state 保留完整 256 位 HMAC tag，使用 hmac.Equal；理想 PRF 下 v_m 次
猜测的通用项为 v_m/2^256，另加 HMAC/HKDF 的计算攻击优势。SHA-256 的通用
碰撞强度约 128 位，不据此把 HMAC 错写成相同的生日伪造预算。CURRENT/meta
摘要、清单摘要和文件名哈希还依赖 SHA-256 的碰撞/第二原像性质：

- CURRENT 的无密钥摘要只定位精确 meta；必须继续验证 meta 的 AEAD。
- 清单根在 state MAC 内认证，逐块/逐条身份与实际文件仍需核对。
- ItemID 文件名哈希不能取代头部完整 ItemID 比较，碰撞时不得覆盖。
- source/target MAC 验证仅证明所选端；不能把未验证的另一端变成删除授权。
- MAC 和摘要不证明新鲜度，旧备份回滚、历史密钥泄露和服务器密码撤销继续遵守 ADR。
